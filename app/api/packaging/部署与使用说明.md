# IE 改善平台 · 单文件部署版 — 部署与使用说明

版本：IE-Platform v1.0.0 ｜ 形态：Node SEA 单文件可执行程序（`IE-Platform.exe`）
适用：Windows Server 2016 / 2019 / 2022（x64），内网或隔离网络环境

---

## 1. 这是什么

原系统为「NestJS + TypeORM + SQL Server」后端（API）+「Vite + React」前端（SPA）。
本发布包把**整个后端与运行时**打进一个 `IE-Platform.exe`（约 95 MB，内含 Node.js v22 运行时与全部依赖），并由该 exe **直接托管前端静态资源**——目标服务器：

- ✅ 不需要安装 Node.js、npm、Visual Studio、.NET 等任何开发/运行时环境
- ✅ 不需要 IIS / nginx 反代（单进程同时提供 API 与页面；IIS 反代为可选）
- ✅ 不需要源代码
- ⚠️ 仍需要 **SQL Server**（数据库外置，连接串在 `.env` 配置）
- ⚠️ 转码用的 ffmpeg 已随包分发（`bin/ffmpeg.exe`），无需单独安装

## 2. 发布包结构

```
IE-Platform-v1.0.0/
├─ IE-Platform.exe          # 主程序：API + 前端托管 + 视频转码调度（唯一可执行文件）
├─ .env                     # 运行配置（数据库连接、JWT 密钥、端口…）★部署前必改
├─ bin/
│  └─ ffmpeg.exe            # 视频转码（82MB）；不转码可删，系统 PATH 有 ffmpeg 亦可
├─ config/
│  ├─ rules/                # 规则引擎 JSON（va_rules / waste_triggers / ecrsa_map …）
│  └─ benefit_params.json   # 收益参数（程序按约定从 rules 目录上级读取）
├─ web/
│  └─ dist/                 # 前端构建产物（SPA），由 exe 直接托管
├─ storage/
│  └─ videos/               # 上传的视频存放目录（运行时自动创建/写入）
├─ logs/                    # 预留目录（当前日志输出到控制台/服务日志）
├─ ie-platform.pid          # 运行后自动生成的 PID 文件（停止脚本用它精准结束进程）
├─ start.bat                # 前台启动（双击即可，Ctrl+C 优雅停止）
├─ stop.bat                 # 停止（按 PID 结束，无 PID 文件时按镜像名兜底）
├─ install-service.bat      # 注册为 Windows 服务（需管理员）
└─ uninstall-service.bat    # 卸载 Windows 服务（需管理员）
```

## 3. 最小运行时依赖清单

| 依赖 | 是否随包 | 说明 |
|---|---|---|
| Windows Server 2016+ x64 | — | 操作系统本体 |
| SQL Server 2016+（Express 亦可） | ✗ 外置 | 数据库；TCP 1433 开放；库名/账号在 `.env` 配置 |
| Node.js 运行时 | ✅ 已内嵌于 exe | v22.22.2，无需单独安装 |
| 全部 npm 依赖（NestJS/TypeORM/mssql/bcryptjs…） | ✅ 已内嵌 | 纯 JS 依赖，全部打进 exe |
| ffmpeg | ✅ 随包 `bin/ffmpeg.exe` | 视频格式归一化；删掉后仅影响非 MP4 视频自动转码 |
| VC++ 运行库 | ✅ 不需要 | Node 官方构建为静态链接，不依赖 VC++ Redist |
| .NET Framework | ✅ 不需要 | — |
| IIS / nginx | ⚪ 可选 | 单进程已含前端托管；需要域名/HTTPS/端口转发时才用 |

## 4. 部署流程（全新服务器）

### 步骤 1：准备数据库

1. 目标机安装 SQL Server（Express 版即可），确认 TCP 1433 已监听（SQL Server 配置管理器 → TCP/IP 启用）。
2. 创建数据库（或复用已有库）：
   ```sql
   CREATE DATABASE CN_AME;
   ```
3. 创建一个应用账号（或用 sa）：
   ```sql
   CREATE LOGIN ie_app WITH PASSWORD = 'YourStrongPassword';
   CREATE USER ie_app FOR LOGIN ie_app;
   ALTER ROLE db_owner ADD MEMBER ie_app;  -- 需建表权限
   ```

### 步骤 2：放置发布包

把整个 `IE-Platform-v1.0.0` 目录拷贝到目标机，例如 `D:\IE-Platform\`。
> 路径含中文/空格均可，但**不要**放到 `C:\Program Files\` 等受 ACL 保护的目录（服务账号默认无写权限，`storage/`、`ie-platform.pid` 需要可写）。

### 步骤 3：修改 `.env`

用记事本打开 `.env`，至少修改：

| 配置项 | 说明 |
|---|---|
| `DB_HOST` / `DB_PORT` / `DB_NAME` / `DB_USER` / `DB_PASS` | 指向步骤 1 的数据库；内网可用 `DB_ENCRYPT=false` |
| `JWT_ACCESS_SECRET` / `JWT_REFRESH_SECRET` | **必须换**：随机长字符串（`NODE_ENV=production` 时 dev- 前缀会被拒绝启动） |
| `METRICS_TOKEN` | 监控抓取令牌，建议更换 |
| `ORIGIN` | 同源部署可不管；若前端与 API 不同域才需要 |
| `SEED` | 空库首次启动自动灌演示数据；正式上线置 `false` |
| `PORT` | 默认 3001，被占用再改 |

### 步骤 4：建表（首次部署必做）

打开命令行，进入发布包目录，执行：

```bat
IE-Platform.exe migrate
```

看到 `SQL Server 迁移完成：27 表 + 12 索引 + 46 项存量升级（库 CN_AME@localhost）` 即成功。
该命令幂等（`IF NOT EXISTS` 保护），重复执行安全；**升级版本时同样执行它**。

### 步骤 5：启动并验证

双击 `start.bat`（或命令行执行 `IE-Platform.exe run`），看到：

```
IE平台 API 启动: http://127.0.0.1:3001/api  db=mssql ...
前端托管: D:\IE-Platform\web\dist
```

浏览器访问 `http://<服务器IP>:3001/` 应出现登录页。
验证接口：`curl http://127.0.0.1:3001/api/health`。
种子账号（`SEED=true` 首次启动自动创建）：用户名 `admin`，密码 `123456`，**登录后请立即改密**。

### 步骤 6（推荐）：注册为 Windows 服务

右键 `install-service.bat` → **以管理员身份运行**，然后：

```bat
sc start IE-Platform     :: 或 net start IE-Platform
sc query IE-Platform     :: 查看状态
```

服务已配置开机自启 + 崩溃 60 秒后自动重启（最多 3 次）。
卸载：管理员运行 `uninstall-service.bat`。

## 5. 日常使用说明

### 启动

| 场景 | 操作 |
|---|---|
| 临时/调试运行 | 双击 `start.bat`，或命令行 `IE-Platform.exe run` |
| 长期运行 | 注册服务后 `sc start IE-Platform` |
| 迁移/升级建表 | `IE-Platform.exe migrate` |
| 灌演示数据 | `IE-Platform.exe seed`（空库有效，不覆盖已有数据） |
| 查看版本 | `IE-Platform.exe version` |

### 停止

| 场景 | 操作 |
|---|---|
| 前台运行 | 窗口内 `Ctrl+C`（优雅停止：关闭连接池、清理 PID 文件） |
| 命令行/服务 | `IE-Platform.exe stop`（读 PID 文件精准结束，不依赖 taskkill） |
| 图形界面 | 双击 `stop.bat`（等价于上一行；PID 文件丢失时按进程名兜底） |
| 服务 | `sc stop IE-Platform` / `net stop IE-Platform` |

> 说明：`stop` 子命令与服务停止都是进程级硬结束。本服务为无状态 API + 连接池由 SQL Server 回收，硬停止无数据风险；`Ctrl+C` 路径才是优雅关闭。

### 配置修改

所有配置都在 `.env`，**改完必须重启**（服务：`sc stop IE-Platform && sc start IE-Platform`）。
常用项：端口 `PORT`、数据库 `DB_*`、AI 开关 `AI_ENABLED` / `AI_SUGGEST_ENABLED`、前端目录 `WEB_DIST`、ffmpeg 路径 `FFMPEG_BIN`、规则目录 `RULES_DIR`。

### 日志

当前日志输出到**控制台/服务标准输出**：
- 前台运行：直接看 `start.bat` 窗口；需要落盘可改为 `IE-Platform.exe run >> logs\console.log 2>&1`
- 服务运行：事件查看器 → Windows 日志 → 应用程序（来源：IE-Platform）
- 建议排障时先用前台方式复现。

### 升级版本

1. 停止旧程序（`stop.bat` 或 `sc stop IE-Platform`）。
2. 用新发布包的 `IE-Platform.exe`、`web\dist\`、`config\` 覆盖旧文件（**保留你的 `.env` 和 `storage\`**）。
3. 执行 `IE-Platform.exe migrate`（幂等，补齐新表/索引）。
4. 重新启动。

## 6. 访问方式

| 用途 | 地址 |
|---|---|
| 前端页面 | `http://<服务器IP>:3001/` |
| API | `http://<服务器IP>:3001/api/...` |
| 健康检查 | `http://127.0.0.1:3001/api/health` |
| 监控指标 | `http://127.0.0.1:3001/api/metrics`（需 `METRICS_TOKEN`） |

> **监听地址**：发布包 `.env` 默认 `HOST=0.0.0.0`（单文件版无反代，需直曝局域网）。
> 若你要前置 IIS/nginx 反代（域名、HTTPS、端口转发），把 `.env` 改回 `HOST=127.0.0.1`，
> 程序只监听回环，由反代层对外——这也是原生产架构的安全形态。

## 7. 故障排查

| 现象 | 排查 |
|---|---|
| 启动即退出，提示 `缺少必需环境变量` / `生产环境必须配置 JWT…` | `.env` 未就绪：确认文件在 exe 同级目录且 JWT 密钥不是 dev- 占位 |
| 提示 `无法连接数据库` / 启动后接口 500 | 检查 `.env` 的 `DB_*`；SQL Server 的 TCP 1433 与防火墙；账号权限 |
| 提示 `规则缺失：DB 与文件均无 …` | `config/rules/` 与 `config/benefit_params.json` 被删/改名，从发布包恢复 |
| 浏览器打不开页面但 health 正常 | 防火墙未放行 3001；或 `web/dist` 丢失（启动日志会显示"纯 API 形态"） |
| 上传视频后无法播放/转码失败 | 确认 `bin/ffmpeg.exe` 存在；或在 `.env` 设 `FFMPEG_BIN` 指向系统 ffmpeg |
| 双击 exe 无反应 | 用 `start.bat` 或命令行启动看报错；检查端口 3001 是否被占用（`netstat -ano \| findstr 3001`） |
| SmartScreen 提示"未知发布者" | 本包未做代码签名：点击"仍要运行"，或用自有证书对 exe 签名 |
| 服务装了起不来 | 确认用**管理员**运行 install-service.bat；`sc qc IE-Platform` 核对路径 |

## 8. 安全提醒

1. **务必修改** `.env` 里的 JWT 双密钥、数据库口令、`METRICS_TOKEN`（发布包携带的是开发/迁移用值）。
2. 种子账号 `admin/123456` 仅用于空库演示，登录后立即改密；正式环境 `SEED=false`。
3. `.env` 含敏感信息，不要提交到 git 或随意外发。
4. 建议通过防火墙限制 3001 端口来源（办公网段），或前置 IIS/nginx 做 HTTPS。
