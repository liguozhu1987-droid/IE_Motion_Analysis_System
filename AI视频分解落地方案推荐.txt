```markdown
# IE 视频动作自动分解 AI 应用路径：低成本技术方案报告

## 1. 方案结论

推荐采用：

> **轻量感知 + 关键点/手部特征 + 时序动作识别/状态规则 + IE浪费规则 + 小模型辅助建议 + 人工确认决策**

即：

```text
作业视频
→ FFmpeg/OpenCV 预处理、抽帧、切片
→ YOLO / YOLO-Pose / MediaPipe 检测人、手、工具、物料、操作区域
→ LSTM / 多尺度时序窗口 / 状态机 判断动作序列和工序步骤
→ IE规则库识别等待、多余动作、重复、转身、搬运、双手不平衡等浪费
→ 小 LLM / VLM 辅助生成改善建议，仅处理低置信片段和报告生成
→ 用户在前端选择：采纳 / 修改 / 忽略
```

该路线适合作为 IE/ME 视频动作分解 MVP，成本低于端到端大模型视频分析，可解释性高于纯黑盒模型。

---

## 2. 方案目标

| 目标 | 实现方式 |
|---|---|
| 视频动作自动分解 | YOLO 感知 + 时序动作识别/状态机 |
| 工序步骤识别 | SOP 步骤序列约束 + 多尺度时间窗口 |
| 浪费自动识别 | IE/精益规则库 |
| 改善建议自动设定 | 规则模板 + IE知识库 + 小模型生成候选建议 |
| 用户决策 | AI 输出证据、置信度、建议，人确认 |
| 成本控制 | 抽帧、事件触发、片段分析、低置信才调用大模型 |
| 可解释性 | 每个动作和浪费都关联时间点、证据帧、规则来源 |

---

## 3. 核心架构

### 3.1 总体流程

```text
视频输入
  ↓
预处理：转码 / 抽帧 / 切片 / 去抖 / ROI 裁剪
  ↓
感知层：目标检测 + 人体/手部关键点
  ↓
特征层：帧级空间特征 → 时序特征
  ↓
动作层：LSTM / 状态机 / 多尺度窗口识别工序动作
  ↓
IE规则层：动作序列对齐 SOP，识别浪费
  ↓
建议层：生成改善建议候选
  ↓
决策层：用户确认、修改、忽略
  ↓
输出：动作时间线、浪费清单、改善建议、标准作业参考
```

---

## 4. 推荐技术选型

| 模块 | 推荐方案 | 说明 |
|---|---|---|
| 视频预处理 | FFmpeg + OpenCV | 统一格式、按 1～2 fps 抽帧、切片、ROI裁剪 |
| 目标检测 | YOLOv8n / YOLOv8s / YOLO11n / YOLO11s | 检测人、工具、物料、包装物、操作区 |
| 人体姿态 | YOLOv8-Pose / RTMPose / MediaPipe Pose | 识别转身、弯腰、手臂动作、身体朝向 |
| 手部关键点 | MediaPipe Hands / YOLO-Pose | 判断抓取、放置、扫码、套袋、封袋等动作 |
| 时序动作识别 | LSTM + 多尺度窗口 / 状态机 | 判断连续动作序列，避免单帧误判 |
| SOP对齐 | 步骤顺序约束 + 命中帧确认 | 判断是否漏步、顺序错误、异常动作 |
| 浪费识别 | IE规则库 + ECRS + 精益浪费规则 | 识别等待、重复、搬运、转身、双手不平衡等 |
| 改善建议 | 规则模板 + 知识库 + 小LLM/VLM | AI给候选建议，不直接替代人 |
| 低置信复核 | 小VLM或轻量多模态模型 | 仅分析模糊片段，降低调用成本 |
| 前端展示 | 时间轴 + 片段卡片 + 建议审批 | 用户可播放证据帧并决策 |

## 5. 轻量感知方案

### 5.1 检测对象建议

先不要做过多类别，建议控制在 8～15 类：

```text
人、手、物料、彩盒、包装袋、扫码枪、工具、传送带、操作台、成品箱、设备状态提示、工具支架、条码区域、工位ROI
```

### 5.2 输出特征

每帧转化为时序特征：

```text
Frame_t = [
  person_box,
  hand_keypoints,
  object_boxes,
  tool_boxes,
  ROI_overlap,
  movement_speed,
  contact_status
]
```

例如：

```text
第1秒：右手接近主机
第2秒：手拿起扫码枪
第3秒：主机与扫码区域重叠
第4秒：手离开主机，物料进入袋口区域
```

这些特征用于判断动作序列。

## 6. 动作识别方案

### 6.1 推荐模型组合

| 组合 | 适用场景 | 成本 | 推荐度 |
|---|---|---:|---|
| YOLO + LSTM | 工具/零件检测明确，动作主要依赖物体状态变化 | 低 | 推荐 |
| YOLO-Pose + LSTM | 精密装配、手部动作明显、需要关键点支持 | 中低 | 强烈推荐 |
| YOLO + MediaPipe Hands + 状态机 | 固定工位、动作规则清晰 | 低 | 推荐 |
| YOLO + SlowFast / TimeSformer | 复杂长视频、高精度要求 | 高 | 后期考虑 |
| 端到端大模型直接看视频 | 快速POC、复杂语义理解 | 高 | 不建议长期主链路 |

### 6.2 动作标签建议

初始动作库控制在 10～20 个：

```text
取料、放置、扫码、检查、翻转、套袋、封袋、装配、贴标、伸手、收回、转身、等待、调整、移动、掉落、卡料、返工、清理、完成
```

### 6.3 状态机示例

```text
动作：扫码
开始条件：右手接近主机 + 扫码枪进入主机区域
过程条件：主机与扫码区域重叠超过 N 帧
结束条件：手离开主机 或 物料状态变化
异常条件：同一物体重复扫码 ≥2 次
```

## 7. SOP 步骤识别方案

适用于有标准作业顺序的场景。

### 7.1 SOP定义结构

```json
{
  "task_name": "主机彩盒扫码打包",
  "steps": [
    {"step_id": "S1", "name": "取主机", "expected_action": "取料"},
    {"step_id": "S2", "name": "扫码", "expected_action": "扫码"},
    {"step_id": "S3", "name": "套袋", "expected_action": "套袋"},
    {"step_id": "S4", "name": "封袋", "expected_action": "封袋"},
    {"step_id": "S5", "name": "放入成品区", "expected_action": "放置"}
  ]
}
```

### 7.2 识别逻辑

```text
视频动作序列
→ 与SOP步骤对齐
→ 判断：完成 / 跳过 / 顺序错误 / 重复 / 超时 / 未命中
```

示例：

```text
实际：取料 → 扫码 → 套袋 → 扫码 → 封袋
判断：扫码重复，疑似扫码失败或确认不足
```

## 8. 浪费识别规则层

这是 IE/ME 最关键部分。浪费识别不建议只依赖模型输出，而应规则化。

| 浪费类型 | 识别规则 | 证据字段 |
|---|---|---|
| 等待浪费 | 连续 ≥3 帧无有效接触、无物体位移、无设备变化 | 时长、空闲手、静止物料 |
| 多余动作 | 同一物体短时间被接近/调整 ≥3 次但未完成动作 | 手轨迹、物体重叠次数 |
| 重复动作 | 同一动作连续触发，超过SOP次数 | 动作序列、计数 |
| 搬运浪费 | 物料移动距离/轨迹超过阈值，或跨区域移动 | 轨迹、ROI距离 |
| 转身浪费 | 人体朝向/肩部关键点变化超过阈值 | 姿态点、朝向角度 |
| 双手不平衡 | 单手操作时长高，另一手空闲比例高 | 左右手接触时长 |
| 动作顺序异常 | SOP步骤顺序错误 | 动作序列、步骤对齐 |
| 瓶颈动作 | 单动作占周期比例超过阈值 | 动作时长、Cycle Time |
| 过度加工 | 同一检查/扫码/封袋超过标准次数 | 动作计数、质量规则 |

示例规则：

```text
if action_sequence == [取料, 扫码, 套袋, 扫码, 封袋]
and 扫码 count > 1
then waste_type = 重复动作/过度加工
```

```text
if hand_idle_time > 2s
and object_position_change < threshold
then waste_type = 等待浪费
```

```text
if left_hand_contact_ratio < 20%
and right_hand_contact_ratio > 70%
then waste_type = 双手不平衡
```

## 9. 改善建议自动设定

AI 应输出“候选建议”，由用户决策。

### 9.1 建议生成来源

| 来源 | 作用 | 成本 |
|---|---|---|
| 规则模板 | 将浪费映射为常见IE措施 | 低 |
| ECRS原则 | 取消、合并、重排、简化 | 低 |
| 动作经济原则 | 减少动作、双手使用、缩短距离等 | 低 |
| 历史案例库 | 类似岗位/工位的改善经验 | 中 |
| 小LLM/VLM | 生成自然语言建议、解释证据、总结报告 | 中低 |

### 9.2 建议结构

```json
{
  "waste_id": "W003",
  "waste_type": "等待浪费",
  "start_time": "00:01:05",
  "end_time": "00:01:08",
  "confidence": 0.87,
  "evidence_frames": ["f_105.jpg", "f_107.jpg"],
  "suggestions": [
    {
      "measure": "将扫码枪固定化，释放右手用于准备套袋",
      "principle": "动作经济原则：减少手持调整",
      "expected_effect": "每循环减少1～2秒",
      "risk": "需验证扫码成功率",
      "user_options": ["采纳", "修改", "忽略"]
    }
  ]
}
```

## 10. 成本控制策略

| 策略 | 说明 |
|---|---|
| 低帧率抽帧 | 建议 1～2 fps，不逐帧大模型调用 |
| 事件触发 | 只分析手/物/工具发生变化的片段 |
| 片段合并 | 将连续相似动作合并为一段 |
| 本地优先 | YOLO/MediaPipe/规则引擎本地运行 |
| 低置信才调用大模型 | 规则置信度 < 0.5～0.7 时送 VLM/LLM |
| 小模型复核 | 使用小VLM或轻量多模态模型处理模糊片段 |
| 结果缓存 | 同工位、同动作、同设备复用模板 |
| 人工反馈闭环 | 用户确认/修改结果回流规则库和训练集 |

建议置信度处理：

```text
≥0.8：直接展示，人工抽检
0.5～0.8：调用小模型复核
<0.5：标记不确定，转人工确认
```

## 12. 方案对标矩阵

| 方案 | 技术路线 | 成本 | 可解释性 | 准确率预期 | 适用阶段 |
|---|---|---:|---|---|---|
| 端到端大模型视频分析 | 直接让多模态模型看整段视频 | 高 | 低 | 可用但不稳定 | POC验证 |
| YOLO + 规则 | 检测物体状态，规则判断动作 | 低 | 高 | 固定工位较好 | MVP主链路 |
| YOLO + LSTM | 检测 + 时序动作识别 | 中低 | 中 | 多步骤识别较好 | 成熟推荐 |
| YOLO-Pose + LSTM | 关键点 + 时序模型 | 中 | 中高 | 精密装配更好 | 推荐升级 |
| YOLO + MediaPipe + 状态机 | 检测 + 手部 + 规则 | 低 | 高 | 动作库固定时好 | IE低成本首选 |
| Video Transformer | SlowFast/TimeSformer等 | 高 | 低 | 复杂场景高 | 后期优化 |
| 工业视频AI平台 | 云端/边缘视觉分析 | 中高 | 视平台 | 偏安全/事件 | 安全场景 |
| 深度动作捕捉/AI生成视频 | 生成动作控制参考 | 不适用 | 低 | 不适合IE分析 | 不建议 |

## 13. 推荐实施路线

### 阶段1：2～4周可行性验证

```text
1. 选 1～3 个典型岗位视频
2. 定义 10～20 个动作标签
3. 定义 5～8 类浪费规则
4. 用云端多模态模型生成 baseline
5. 输出动作时间线和浪费清单
6. IE/ME人工评价
```

验收目标：

```text
动作识别准确率 ≥70%
时间边界误差 ±2秒内
浪费识别精确率 ≥60%
改善建议有效率 ≥30%
```

---

### 阶段2：1～2个月低成本主链路

```text
1. FFmpeg/OpenCV处理视频
2. YOLO检测关键对象
3. MediaPipe/YOLO-Pose获取手部/身体特征
4. LSTM或状态机识别动作
5. 规则引擎识别浪费
6. 知识库生成改善建议
7. Web前端支持用户确认
```

此时主路径：

```text
本地轻量模型 + 规则引擎 + 小LLM辅助
```

---

### 阶段3：持续优化

```text
1. 积累人工确认数据
2. 微调工位专用YOLO
3. 建立动作-浪费-改善映射库
4. 对高误差场景引入更细时序窗口
5. 必要时引入小型动作Transformer
```

---

## 14. 关键工程注意事项

| 风险 | 应对 |
|---|---|
| 视角遮挡 | 采用俯拍或侧俯拍，避免身体/设备遮挡手和操作物 |
| 动作边界模糊 | 使用多尺度窗口，允许时间弹性，容忍动作变慢 |
| 单帧误判 | 必须结合连续帧和状态机，不依赖单帧结论 |
| 标注成本高 | 先做片段级标注，不逐帧精标 |
| 大模型幻觉 | 大模型只生成建议，必须绑定规则和证据 |
| 用户不信任 | 输出证据帧、时间点、置信度、规则来源 |
| 现场差异大 | 每个工位单独配置ROI、动作模板、SOP |
| 浪费规则误报 | 设置阈值、持续时长、次数下限，人工可修正 |

```text

成本：本地轻量模型为主，大模型仅辅助
可信度：证据帧 + 时间点 + 规则来源
```

这是当前最适合 IE/ME 视频动作自动分解、成本可控、可解释、可落地的方案路径。
