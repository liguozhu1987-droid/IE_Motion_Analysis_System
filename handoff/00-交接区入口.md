# 项目管理交接区 · IE Motion Analysis System

> **本目录是所有 Agent / 开发者唯一的任务交接与状态管理区。**
> 每个会话开始先读本目录；每完成一个任务（或中断、或被阻塞），必须把进展写回本目录，下一个会话才能无缝接手。
> 数据库等硬性规则的最高优先级文件仍是仓库根目录 `CLAUDE.md`，本区所有文件与它冲突时以它为准。

## 与 memory-bank/ 的分工（2026-11-22 起）

本目录管**过程与正文**；仓库根目录 [`memory-bank/`](../memory-bank/README.md) 管**可检索的原子结论**（facts / decisions / handoffs / logs），命令入口 `/memory-bank`。

- 长期事实 → `memory-bank/facts/`（status: draft → 人工确认 confirmed）
- 方案取舍 → `memory-bank/decisions/`
- 单次跨 Agent 接力单 → `memory-bank/handoffs/`（pending / claimed / done）
- **同一条事实只有一个正文来源**；facts 是指针卡片，不复制本目录正文。
- 看板 `02-任务看板.md` 是全局任务状态的**唯一准绳**，`memory-bank/handoffs/` 的状态须与它一致。

## Agent 工作流（强制）

1. **接手时**：读本文件 → `01-项目记忆.md` → `02-任务看板.md`（认领任务）→ `04-规则与纪律.md`；需要细节口径/风险/历史时再进 `明细/`。
2. **开工时**：在看板对应任务行把状态改为「进行中」，署名（Agent 名 / 会话标识）+ 日期。
3. **收工时**（无论完成、中断还是被阻塞）：
   - 看板行更新状态与日期；
   - 在 `03-开发记录.md` 顶部追加一条日志：日期、Agent、做了什么、产出/验证结果、遗留问题、下一步建议。
4. **原则**：交接区文件只记录**状态与事实**，不粘贴大段代码或日志；详细证据给出文件路径或测试输出摘要。
5. 新任务先登记到看板再动手；发现规则与 `CLAUDE.md` 冲突时以 `CLAUDE.md` 为准并立即在看板登记修订事项。
