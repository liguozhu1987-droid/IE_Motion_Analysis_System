# Agent 工作规矩 · 需求调研 / PRD / 方案比对（research）

> 适用：行业最佳实践调研、竞品对标、方案选型、机会验证、PRD 撰写。
> 开工前先按 `handoff/明细/project_memory/README.md` §三 读完总入口，再进本目录。

## 一、调研纪律

- **联网核实现状事实**：行业产品、版本、发布日期、客户案例属 present-day fact，
  必须联网检索，不得凭训练印象作答；结论标注数据时点。
- **一手来源优先**：厂商官网 / 客户新闻稿 / 行业媒体 > 聚合站 > 二手转述。
- **区分三类数字**：① 客户公开披露 ② 厂商自述 ③ 厂商内部建模。
  ②③ 一律标注「未经第三方审计」，**不进验收基准、不进 ROI 测算**。
- 单一来源不够时做交叉验证；跨源对比用综合检索而非反复单条搜索。

## 二、方案比对的输出格式

每条候选给：解决什么痛点 / 依赖哪些现有模块 / 改动成本档（零 DDL｜仅规则集发布｜需迁移）/
可逆性 / 可验证的验收口径 / 反证条件。
**不给工期数字、不给成本金额、不编转化率**（口径见 `business_rules.md` 与产品哲学）。

## 三、机会验证门槛（沿用专家团口径）

- 新功能先问「过去怎么做的、上一次花了多久」，用**过去行为**而非意愿判断需求。
- 周活 ≥3 且采纳 ≥50% 才留；≥3 名 IE 说没此痛点即停止，不进 PRD。
- 功能过闸门才留；提示文字不上页面（收进 `?` 帮助浮层 / 独立说明文档）。
- 「验证失败就加功能」是反模式：先查口径、证据链与回归门，再考虑加能力。

## 四、本项目的对标参照（2026-11 已核实，复用即可）

- 品类分水岭：能否产出**可辩护的标准时间（PMTS 口径）**；主流是「AI 起草 + 工程师签核」。
- 五层最佳实践：A 采集 / B 分解 / C 浪费与 VA 分析 / D 产出与应用 / E 部署治理。
- 标杆：Retrocausal Kaizen Copilot、Coats Digital GSD RealMotion（2026-08 发布）、
  Invisible AI、PowerArena HOP、Drishti、DeepHow、Yamazo Studio、OTRS+AI、AVIX、
  TiCon/TiConaut、Proplanner、VIOOVI ECRS。
- 六个坑：AI 建议不当标准 / 变帧率素材不可作时间基准 / 重复播放不产生新样本 /
  隐私与劳资协商不可跳 / 多人遮挡 ID 串号 / OEE 工具不等于工时研究。
- 完整对标矩阵与差距结论见 `deliverables/系统功能全面评审与行业最佳实践对标_20261118.md`。
