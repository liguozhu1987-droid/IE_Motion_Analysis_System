# 项目记忆 · IE Motion Analysis System

> 长期有效的项目事实。更新于 2026-11-20。硬性规则以根目录 `CLAUDE.md` 为最高优先级，本文件不复述口令等敏感信息。

## 1. 项目定位

- **是什么**：IE 动作分析系统 = 「AI 赋能的 IE 分析改善效率工具」。对工位作业视频做动作分解（动素级），自动算 VA/RNVA/NVA、平衡率、瓶颈，给出改善建议并估算收益。
- **部署环境**：企业内网 Windows + SQL Server（生产库 `CN_AME`@`IRSCNYTFINEREPORT.ap.inalfa.local`），同实例另有 CMC 产能库与统一身份认证 SSO 表。并发口径 50+ 人。
- **产品哲学**：工具做「薄」不做「全」——帮 IE 更快看出问题 → 留；帮管理层管住 IE → 砍。审批、追踪、核算类管理功能砍掉或延后。
- **工具主线**：「人拆 AI 校」——人负责视频分解，AI/规则引擎负责校验、归类、诊断、建议。

## 3. 数据模型（2026-11-20 已落地）

- `migrate.ts` 建表范围 = `CLAUDE.md` §1.2 白名单的 **30 张 `t_` 表**，逐一对应，无越界。域分组：租户/用户/权限（tenant、user、role、permission、user_role、role_permission、refresh_token、password_reset）、规则（rule_set）、主数据（project、line、station、station_collaborator、line_share）、业务（element、improvement）、视频（video_asset、video_derivative）、AI（ai_task、ai_suggestion_batch、ai_suggestion、ai_custom_dict、ai_setting、ai_llm_profile、ai_waste_batch、ai_waste_finding、ai_waste_issue、ai_waste_kb）、审计（audit_log）。
- 实体文件在 `app/api/src/entities/`（18 个文件聚合定义），实体与 DDL 双轨维护，改结构三步走：实体 → migrate.ts 幂等 DDL → 更新 `CLAUDE.md` 白名单（需用户书面同意）。
- 生产 `NODE_ENV=production` 时 TypeORM `synchronize=false`，禁止靠同步自动建表。
- 两个手工 SQL（`deploy/sql/manual/2026-11-06-auth-sso.sql`、`2026-11-06-video-retention.sql`）补齐 migrate 之外的增量列（`t_user.auth_source`、`t_refresh_token.source`、`t_video_asset` 保留策略 5 列）；**只跑 migrate 不跑手工 SQL 会导致登录和视频模块失败**。
- 种子数据（`npm run seed`，幂等）：5 用户 / 12 角色 / 26 权限 / 6 规则组 / 6 项目 / 2 产线 / 3 工位。

## 4. 领域口径（改代码前必须遵守）

- **动素三分法**：19 类 = 有效 9（→VA）+ 辅助 5（→RNVA）+ 无效 4（→NVA）+ 其他兜底；并入公司标准 22 类型后词表共 41 类（`motion_standard` 规则集）。
- **RNVA（不是 NNVA）**：必要非增值只能压缩不能直接删，全链路符号统一。
- **VA 归类单一来源** = `va_rules` 规则表（可配置+版本号 rv）；改判必须带结构化标记 `[VA改判|原:x|新:y|理由:z|人:w|日期]`。
- **收益公式固定**：`节省秒数 × 日产量 × 365 × 费率(元/h) ÷ 3600 × 落地率`；费率/日产量无默认值，未配置即阻断（不猜）。
- **版本语义**：工位版本 = 复测代数；复测 = version+1 封存旧版，封存版只读。
- **CMC 铁律**：CMC 产能库全程 SELECT-only；公司/产线/项目/分配以 CMC 为单一数据源；不可达 → 明确提示宁缺勿错，不伪造数据。
- **AI 三铁律**：①AI 建议永远「待审」态；②LLM 禁产数字（定量结论一律规则引擎算）；③模拟值绝不回写正式数据。
