0. 定位：只做加速器一句话原则

判断标准：这个功能是帮IE更快看出问题、更快做出改善，还是帮管理层管住IE？
前者——保留；后者——砍掉或延后。

工具的全部价值就三句话：视频分解快、增值分析快、改善建议快。 除此之外的一切——审批、追踪、核算、报表、认证、仪表盘——要么砍掉，要么用一张Excel代替。

0.1 三条铁律（只留三条，不设关卡体系）

① AI只建议、不执行：建议清单上的每一条都要IE点"确认"才会进实施，系统里不存在"一键执行"。
② 数字由规则算、LLM不产数字：工时、节省、平衡率全部由公式计算；AI只写建议文字描述。
③ 数据质量靠校验拦截+抽审、不靠审批：工时由IE本人负责录入，3条即时校验（必填完整性/时间轴重叠/循环数<15）命中即拦截提交；IE主管每月抽查10%兜底。版本只记录"谁改、何时、改了什么"，不走审批流。

1. 保留的6个核心能力全部围绕"提效"

#能力规格要点省掉的时间
1视频分解工作台
（核心中的核心）		时间线+要素编辑器：双击分割、拖拽调边界（帧级）；双手双列；循环识别（≥15循环，CV>0.15加测至25）；一键抽BEST/WORST Lap；浪费框选即计时（时间线橙色）；异常要素标记（必填原因，不进ST）；提交前即时校验（必填完整性/时间轴重叠/循环数<15，命中即拦截）；分解结果直接写库，零二次导入；Excel导入兼容存量工时手写记录+Excel转录
（原来2~3h）
2精简BOL工时表只3张表（工位/要素/建议），要素15个核心字段；要素类型10类；保留VA分类、工时、循环、评比、宽放、版本；不做物料主数据、不做SOP步骤表告别散落Excel
3一键增值分析分解完自动按规则表归类VA/NNVA/NVA（规则可配置）+饼图+6类浪费清单（持住/重复取放/搬运/等待/寻找选择/检验冗余）+每条带量化证据；低置信度直接进"待复核"小队列逐条人工判断
（原来2~4h）
4一键平衡诊断山积图（VA/NNVA/NVA三色分段+TT线）+平衡率+瓶颈榜+双手作业图自动生成；计算口径：工位工时=Σ生效且非异常要素ST，异常要素单列显示（数量+原因）、不进山积图但可见；换型/改善后一键重算手绘山积图
（原来半天）
5改善建议清单12条高频ECRSA映射（治具代手持住/合并取放/工具定点/料架移入前臂区/供料唯一化/对称布局/双巢作业/包装开槽/来料定向/快换/重叠内外时间/SOP把判断变动作）+简化优先级（节省工时×频次÷难度）+建议书生成（LLM可选开关，不开也能用）想不出改善点、写不出建议书
6改善前后对比改善后复测一次→点"开始复测"自动把当前分解封存为只读v(n)→新旧两版要素工时并排对比→一行收益估算：节省秒数×日产量×365×综合费率（元/工时，含÷3600秒→时换算）×70%落地率（三项参数由IE主管一次性写入配置，公式固定）；自动生成一页对比报告（导出PDF/PPT）改善效果说不清
这6项覆盖了原8步流程中90%的耗时：步骤1~2（分解）、3（更新工时）、4（增值分析）、5（改善计划）、6（操作分析）、8（更新BOL）。步骤7（跟踪）降级为一个"状态列"，不做系统。

2. 明确不做什么砍掉的部分 + 轻量替代

砍掉/延后替代做法（能跑就行）为什么砍
六节点工时审批流IE录入，3条即时校验命中即拦截提交（必填完整性/时间轴重叠/循环数<15）；主管每月抽审10%兜底；版本只记"谁改何时改了什么"审批不产生分析价值，只产生等待
ECN/SOP变更管理闭环SOP导出时自动带版本号；方法变了IE口头通知班长这是管理动作，不是分析能力
S1~S10状态机+关闭码+会签矩阵建议清单加一列状态：待实施 / 已完成 / 已验证三态足够，十态是负担
效益核算体系（Hard/Soft/NWC、财务签认）一行估算公式，IE自己算，不进财务口径要财务认账时再用Excel做，不必内建
三层KPI+仪表盘+人效月报不做；需要时从系统导Excel给管理层看的东西，先不做
五级认证/技能矩阵/培训签认不做；新人直接跟一次分解就会工具上手门槛本身就是设计目标
G1~G12十二道审核关卡只留2条红线：①取消检验类改善须品质确认 ②涉及弯腰/扭转/高举的改善须人因复核12道是官僚，2条是底线
知识库/RAG案例库延后（P2，等积累了30+条改善案例再说）冷启动阶段检索不到东西
标准要素库（新品报价复用）延后（P2，等要素数据积累到200条再说）没有数据量的库没有用
数据迁移五步双轨并行试点线直接用+Excel导入存量工时一条线的迁移不需要方法论
周站会/月报会/季度评审会不做制度化会议；有事在工位现场说工具不负责制造会议
瘦身后仍保留的"重"功能只有一个：视频分解工作台。因为它是全流程的入口，也是替代2~3小时手工活的关键——这一块要做扎实（对标OTRS10交互），其余全部轻量化。

4. 精简数据模型3张表，够用

表核心字段（15个/表以内；t_element因封存需求为16个）
t_station 工位station_id / line_id / name / CT / TT / version / updated_by / updated_at
t_element 动作要素element_id / station_id / seq / start_ms / dur_s / hand / type（10类）/ desc / va_class / outlier_flag / outlier_reason / video_id / rating / allowance / std_time / bol_version
t_improvement 改善建议imp_id / station_id / element_ids / waste_type / method（E/C/R/S）/ measure / est_save_s / priority / status（待实施/已完成/已验证）/ owner / due / before_ct / after_ct

要素类型10类：装配 / 使用（含加工）/ 取放（伸手-握取-移物-放手）/ 预对 / 检验 / 搬运 / 等待 / 寻找选择 / 持住 / 其他。每类带默认VA判定，人工可改（改必填理由）。

没有审批表、没有状态流转表、没有审批日志表、没有物料主数据表、没有KPI表——这些都能用"字段+Excel"替代。唯一新增的是t_element的bol_version字段（分解版本号）：点"开始复测"时当前分解自动封存为只读v(n)，新分解写v(n+1)，前后对比基于两版做差。审批和财务签认砍得，"留底"砍不得——没有旧版数据，改善前后对比就是无源之水。

5. 只有4个页面点到点，不绕路

① 工位清单

选线体→工位卡片（CT / VA占比 / 上次分析日期 / 状态）。一键新建工位、Excel导入存量工时。

② 分解工作台（核心页）

左边视频（倍速/逐帧/局部放大），右边双手时间线；双击分割、拖拽边界；下方属性面板（类型/描述/工时/异常标记）；顶部一键"抽BEST/WORST"。

③ 分析结果页（一屏看全）

VA/NNVA/NVA饼图 + 6类浪费清单（带证据）+ 山积图 + 瓶颈榜 + 改善建议清单（可勾选采纳）。

④ 改善对比页

改善前后要素工时并排 + 一行收益估算 + 导出PDF/PPT对比报告。

页面之间只有一条主路径：工位清单 → 分解 → 分析 → 建议 → （改善后）复测对比。没有权限矩阵、没有多级菜单、没有配置中心（规则表用JSON文件维护即可）。

7. 验收标准与"加回重功能"的闸门

7.1 验收指标（达不到就不扩线）

指标目标说明
单工位全流程耗时≤30分钟分解+分析+建议（现状2~4小时）
分解录入耗时≤1小时/工位1~2年经验IE可胜任
试点线跑通工位5~10个至少覆盖1个瓶颈工位
建议产出≥1条/工位，且≥1条被实施验证"分析真的能变成改善"
IE主动使用每周≥3次打开不被要求也在用，才算成功

7.2 什么条件下才加回重模块（闸门）

加回条件才允许增加
试点线周活≥3次、建议采纳≥50%扩到第二条线
案例库自然积累≥30条（IE主动记录）加RAG案例检索
财务/管理层明确要求报数口径加效益台账（仍不做Hard/Soft体系）
IE主动抱怨"版本乱了/找不到谁改的"才加审批或版本治理
要素数据≥200条且新品报价频繁加标准要素库
反向铁律：没到闸门条件，一律不加功能。管理层的报表需求先用Excel导出顶住——工具的价值在于让IE多分析几个工位，不在于让管理层多几块看板。
