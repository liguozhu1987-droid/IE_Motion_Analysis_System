## 二、三方意见要点

### 标准工时专家（8.0/10）

**做对了的**：播放中不中断打 S 粗切（≈连续测时法取形，打点误差 ±1 帧 vs 掐表 ±0.2s）；按实测帧率步进 + 毫秒时间码（可复核的原始数据链）；Enter/D 连续记录；本地草稿 + 版本封存；异常要素不进 ST。

**问题**：
- **P0-1** 评比/宽放逐要素即时录入、默认 1.0/0.15——实务中评比按"操作者×循环"集中评定（西屋法四因子），宽放按作业强度分档；逐要素默认值 + 回车连跳 = 诱导"全默认到底"，产出**虚假精确的 ST**
- **P0-2** 循环数引导后置——V3 门槛（≥15、CV>0.15 加测至 25）在提交校验时才触发，前期零引导，必然返工
- **P1** 30fps 对 <0.15s 动素级短要素判读误差可达 20%；跨工位复用沿用原评比宽放 → ST 虚假一致

### 标准作业专家（7.5/10）

**做对了的**：10 类要素粒度选在"一打点=一要素"的可执行层（比 17/21 动素粗、比传统四类细）；VA 自动带出 + 改判留痕；版本封存与 ECN 实务对齐；帧级精修是 ST 地基。

**问题**：
- **P0** 手别是要素单属性、无并行时间轨道——双手分析的本质是**同一时间窗的两条并行要素**（左手持住时右手装配），现状要么合并成 B（信息丢失），要么串行两条（重叠无处安放），双手图是伪图
- **P1** 描述自由文本 → "取螺丝/拿螺钉/抓螺钉"同义泛滥，复用靠运气匹配
- **P1** 复用旧版后无版本 Diff 视图，变更影响靠人脑比对
- **P2** 改判写理由落在分解热路径上

### IE 培训教练（7.5/10）

**做对了的**：VA 自动带出（最大降负荷设计）；D 同上 + 复用是"越拆越快"的核心引擎；回车闭环无断点；本地草稿让新手敢乱点。

**问题**：
- **P0** 页面零提示 + 核心动作（被其理解为）无按钮路径——新手不知道 `?` 能开帮助；触控板/手套场景纯键盘是断点
- **P1** 撤销 8 秒太短——误删高发在第 3 个工位后的疲劳段，发现常在 10 秒之后
- **P1** 类型误选会被"改判留痕"误伤，逼新手将错就错
- **P1** 打点粒度无示范（打多细？），首次打点必然犹豫

### v3.13 实施规格（向三方通报的细化决策）

1. **批量评定**（回应工时专家 P0-1）：评定状态三态 `rated: 'hand' | 'batch' | undefined`，取值优先级**手改 > 批量 > 默认 1.00/0.15**——任何手工编辑都永久覆盖批量值，杜绝"批量一抹再手改"的口径漂移。范围默认"没动过的"（防覆盖手改），可显式选"全部"。CT 头部星标 + 脚注"*含未评定要素，按默认 1.00/0.15 计"——**不假装精确**。
2. **版本 Diff**（回应作业专家 P1）：LCS 配对（键 = 描述 + 类型），无描述要素按起始时间 ≤50ms 贪心前处理；未配对要素就近 ≤200ms **且描述兼容**（相等/包含/相似度≥0.6 且长度差≤4）才判 MODIFY，否则保持新增/删除——防止"描述完全无关却被静默并成修改"的误导（单测 15 项锁定，含该反例）。描述改写不拆行，行内标注「描述」并入 changed 集。**只读视图，无任何回写入口**（AI 建议永远待审的铁律在数据层同样成立）。
3. **打点粒度示意**（回应教练 P1）：不依赖图片素材——"粒度口诀：手一停，就打点"横幅 + 原来三问（停了？/换了？/性质变了？）+ 3 张正反卡（"取料并装上"要拆 3 个 vs "连续小移动"不拆）+ 色块条（60 秒工位约 10~12 个要素）+ 三步自检。用纯文字与色块讲清"打多细"。
4. **循环引导 + 帧率提示**（回应工时专家 P0-2 / P1）：循环数 <15 或 CV>0.15 时交付条实时出文案引导（V3 门槛前移至分解过程中，不再等提交校验才拦截）；帧率 <30 时监看区出警示，明确 0.15s 短要素误差超 20% 的量化后果。

# 附：v3.14 现场使用反馈整改（2026-10-22，用户 4+1 项）

蓝图落地后进入真实使用，用户提出 4 项问题 + 1 项追加，本轮全部实施完毕。四项均超出"界面微调"范畴，其中第 3 项是数据模型级升级。

| 反馈 | 根因 | 处置 |
|---|---|---|
| ① 加要素后视频播放区变小 | 头部 ct-note/flash/undo/banners 与交付条 hint 均为**随状态增高的流式元素**，measure 重算即压缩视频 | 提示全部浮层化（`.wb-toast` absolute）；ct-note 并入指标格；hint 改固定 22px 单行条；measure 安全网监听头/模式条/交付条 |
| ② 时间线拖边界无磁吸，难与目标时刻贴合 | 拖拽仅按像素比例换算，无对齐辅助 | 参考 ELAN/Premiere 边缘吸附实践：候选=相邻要素边界（同手优先，8px 容差）+播放头+0 点；拖拽中出竖向参考线与时间浮签；磁吸后再按帧量化 |
| ③ 分类按动素三分法重构（有效/辅助/无效） | 原 10 类粗分无法体现动素性质，VA/NVA 判定颗粒度不足 | **类型体系 10→19 类**：有效 9（伸手/握取/移物/定位/装配/拆卸/使用/放手/检查→VA）、辅助 5（寻找/发现/选择/思考/预置→RNVA）、无效 4（持住/可避免延迟/不可避免延迟/休息→NVA）+其他兜底；va_rules 升 RV2.0（19 条规则逐类型定义默认与例外）；存量 742 行零残留迁移；浪费触发器仅迁移类型过滤器（浪费类别名保留） |
| ④ 描述标准化（动词+对象+介词+位置+行程） | 自由文本描述无法检索、汇总、建模 | 检查器新增「结构化描述」：动素（自动取当前类型）+操作对象+介词+位置要素+动作行程，实时组合预览（如"握取 前横梁 于 物料箱（手指）"），一键写入；草稿跨要素保留，重复动作只改差异字段 |
| ⑤（追加）展开时间线后视频被压缩变形 | 时间线面板为栅格下方流式展开，展开即吃掉视频高度 | **右列模式切换**：属性检查器 ↔ 时间线/清单二选一，面板改为栅格右列内嵌 + 恒定高度模式条；视频宽/高/位置与面板状态完全解耦（实测 792×573@268 零变化） |

**关于第 4 项的行业实践说明**（回答"是否有固定描述模式"）：MOST/MTM 体系的标准动作描述即"**动素（动词）+ 操作对象 + 介词 + 位置要素**"，高级别再叠加**动作行程**（大臂/小臂/手腕/手指）与**控制方式**（脚控/眼控）。本工具的 19 类动素名即动词表，类型字段就是标准化的动词——描述按此结构书写后，同构描述可被检索、按对象/位置汇总、直接建立数据模型（后续做动作库/标准数据复用）。

**验证**：冒烟 137/137 + 联调 31/31 + 驾驶舱 30/30 + Diff 单测 15/15 + 认证管理 48/48 + UI 专项 35/35 + 工作台 13/13 + 帧率 15/15，全套零破坏。截图：`deliverables/screenshots/v314-default.png`（属性模式）、`v314-timeline-mode.png`（时间线模式，视频满幅）、`v314-structured-desc.png`（结构化描述）。
