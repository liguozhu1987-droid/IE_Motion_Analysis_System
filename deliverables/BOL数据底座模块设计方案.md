# BOL工时数据底座模块设计方案

> 「工业工程IE专家团」AI分析改善效率工具 · 数据底座章节（v1.1，含与线平衡模块接口协调增补）
> 起草：标准工时专家 毕准时 | 依据：ie-playbook 第5/7/8/10册（动素分析、时间研究、标准工时体系、MOST）
> v1.1变更：①要素层新增4个自动化支撑字段（起始时间戳/动作等级/移动距离/对象物料）+ va_confidence/va_class_default字段；②新增t_material物料主数据表；③新增VA归类规则单一来源条款（4.4节）

---

## 0. 设计总纲（结论先行）

1. **地基是"四层一码"**：产线→工位→作业单元→动作要素四层结构 + 全局统一编码规则。VA/NNVA/NVA三分类是AI增值分析的主索引，必须在数据层原生落字段，不能事后补。
2. **主线坚持"人拆AI校"**：AI不做视频自动动作分解（与用户方向一致），主线是"人工结构化分解 + AI规则引擎/LLM校验查漏"。AI视频分解仅留作远期试点，且设精度准入门槛（与人工标注偏差<10%才可扩量）。
3. **三个权力必须留在人手里**：评比定值权、宽放定值权、发版批准权。AI只做异常检测、横向比对、理论值校核——提示，不定值。依据手册铁律：**评比给依据、宽放靠实测**。
4. **迁移不冲击运作**：冻结模板→单线试点→历史数据映射清洗→双轨并行1~2月→切换发版，老Excel归档只读。
5. **沉淀目标**：3~6个月形成首个产品族的"动作要素级标准工时库"（标准资料法思路），让工时制定从"测"进化到"查"，直接反哺新品报价/转产预估。

## 1. BOL工时数据结构标准化设计

### 1.1 四层层级结构总览

```
产线 LINE ──1:N──> 工位 STATION ──1:N──> 作业单元 OPERATION ──1:N──> 动作要素 ELEMENT
```

| 层级 | 定义 | 数量级 | 分界标准 |
|---|---|---|---|
| 产线 | 一条物理产线/一个TAKT单元 | 全厂5~30条 | — |
| 工位 | 一名（组）操作员+设备构成的最小排产单元 | 每线8~30个 | 按SOP工位划分 |
| 作业单元 | 有**肉眼/耳听可辨分界点**的一组动作（取/装/锁/检/放） | 每工位5~10个 | 分界点必须写进字段（如"听到咔哒声""手离开工件"） |
| 动作要素 | 动素级/ MOST序列级最小分析单位，AI增值分析的对象 | 每单元1~8个 | 左右手分别记录 |

**层级铁律**（进开发需求文档的硬规则）：
- 工位标准工时 = Σ(生效要素标准工时 × 频率)，**系统计算列，禁止手填覆盖**；
- SOP未固化的作业单元禁止发标准工时（方法没定型测了也白测）；
- 每个要素必须挂接视频证据（video_id）或预定时间法编码（MOST/MOD），二者至少其一，否则校验不过。

#### 表4：动作要素层 `t_element`（核心表，AI分析的数据源）

| 字段 | 类型 | 必填 | 说明/规则 |
|---|---|---|---|
| element_code | varchar(20) PK | 是 | `{operation_code}-E{两位序号}-V{版本}`，如 L01-ST10-OP03-E02-V2 |

| operation_code | varchar(16) FK | 是 | 所属单元 |
| element_seq | int | 是 | 要素顺序 |
| element_name | varchar(50) | 是 | 受控词表命名，禁自由文本 |
| element_type | varchar(4) | 是 | 要素类型码（见1.4，E10~E130） |
| va_class | enum | 是 | **VA / NNVA / NVA**——类型默认值由系统带出；模糊情形由线平衡分析引擎归类后回写（VA规则单一来源条款见4.4），人工可覆盖，覆盖必填 override_reason |

| hand | enum | 是 | L / R / 双手 |

| motion_level | tinyint | 条件 | 动作等级1~5（1手指/2手腕/3前臂/4上臂/5肩躯干）；E10/E20/E95/E120类必填，系统按类型默认带出、人工只改偏离项 |
| move_distance_cm | decimal(6,1) | 条件 | 取放/移动距离，按档位下拉（≤15 / ≤30 / ≤50 / >50cm）；E20/E120类必填 |
| material_id | varchar(20) FK | 条件 | 操作对象物料，关联 t_material（见表5）；E10/E20/E40/E50类必填，支撑搬运/供应链类改善分析 |
| therblig | varchar(6) | 否 | 动素符号（TE/G/TL/A/DA/U/RL/I/SH/F/ST/PN/PP/H/UD/AD/R） |

| data_source | enum | 是 | 秒表实测 / MOST / MOD / 标准库类推 / 改善验证复测 |

| measured_by / measured_date | varchar(20) / date | 是 | 测定人 / 测定日期 |
| status | enum | 是 | 草稿 / 待审 / 生效 / 作废 |
| valid_from / valid_to | date | 条件 | 生效/失效日期 |

### 1.3 Excel自由格式BOL → 结构化迁移五步（不冲击日常运作）

| 步骤 | 动作 | 周期 | 不冲击保障 |
|---|---|---|---|
| ① 冻结模板 | 现有Excel BOL**只读冻结**（不再改格式），发布结构化模板+受控词表 | 1周 | 日常生产继续用老表 |
| ② 单线试点 | 选1条瓶颈线，IE用新模板+系统重录（含补拍视频） | 2周 | 只动一条线，其余照旧 |
| ③ 历史映射清洗 | 规则引擎/AI做历史Excel字段映射 → 输出**脏数据清单**（缺评比依据、CT当ST、单元无分界点、无宽放构成）→ 人工只处理清单上的工位 | 并行 | AI干粗活，人只做判断 |
| ④ 双轨并行 | 老Excel只读参考、新库主用；每周对账，**差异>±5%的工位安排复测**，不搞一刀切 | 1~2月 | 复测发现真实问题反而是收益 |
| ⑤ 切换发版 | 老表归档只读，新库唯一生效；老表历史数据可追溯导出 | — | 版本链保证任何历史时点可回溯 |

### 1.4 动作要素类型分类标准（AI可判断的14类实用清单）

以18动素为理论基础、MOST三大序列为校核口径，**合并为14个AI从文字描述即可判定的类型**，每类带默认VA判定与改善方向（即AI增值分析的判断底表）：

| 类型码 | 名称 | 动素/MOST来源 | 默认VA | AI改善提示关键词 |
|---|---|---|---|---|
| E10 | 取料（伸手+握取） | TE+G / Get | NNVA | 缩短距离、固定位置、滑道/磁吸取放 |
| E20 | 移动/传递 | TL | NNVA | 距离、动作等级（前臂3级黄金域） |
| E30 | 放置 | RL+放置 | NNVA | 滑槽/弹射取消放手 |
| E40 | 装配/插装 | A / ABP | **VA** | 治具导向、预对位 |
| E50 | 锁附/紧固 | U(L/F) | **VA** | 首选手动改善，自动化最后招 |
| E60 | 检验/测试 | I / U(M) | **VA**（规定检验项） | 治具/传感器代目检 |
| E70 | 拆卸 | DA | VA（返工场景=NVA） | 结构优化免拆 |
| E80 | 持住 | H | **NVA** | 治具/夹具代替手（头号敌人） |
| E90 | 寻找/选择 | SH/F/ST | **NVA** | 定点定位+颜色编码、唯一化供料 |
| E95 | 预对/翻面 | PP | NVA | 治具导向、对称件改非对称 |
| E100 | 等待-设备 | MOST X / UD | **NVA** | 人机联作分析、双巢化 |
| E110 | 等待-人员/延误 | UD/AD | **NVA** | 平衡重排、供料改善 |
| E120 | 走动/转身 | W5/B17 | **NVA** | 布局问题，必须改 |
| E130 | 清洁/擦拭/偶发处理 | 变异单元 | NNVA | 频率必须实测，禁止摊薄进定期单元 |

**三条硬规则**：① 默认VA判定+人工可覆盖（留痕）；② 系统自动统计各工位**NVA占比，>10%自动触发改善警报**（手册铁律：第三类动素占比>10%就是大窟窿）；③ 类型×对象特征（重量/距离/精度档）是后续标准要素库的索引键。

## 2. 动作分解与工时采集的人机协作设计（流程步骤1/2）

### 2.1 人工视频分解 vs AI视频分解对比与采用建议

| 维度 | AI视频自动分解 | 人工分解（资深IE） | **人工分解+AI校验（推荐主线）** |
|---|---|---|---|
| 单工位成本 | 高（算力+标注训练，每新工位类型需再标注） | 高（资深IE 1~2h/工位，且资深人稀缺——正是公司痛点） | **低**（1~2年IE按模板录入0.5~1h + AI校验秒级） |
| 精度 | 双手交叉/遮挡/亚秒级微动作识别不稳，错误分解会**污染整个工时库** | 高 | 较高（人拆解+AI规则查漏兜底） |
| 上线周期 | 需数月标注+调优 | 立即可用 | **立即可用**（规则引擎先上，LLM校验后上） |
| 风险 | 错误数据带"AI"光环反而没人质疑 | 依赖个人经验，质量参差 | 规则透明可审计，错误可追溯到人 |
| 适用场景 | 动作幅度大、单手、重复性高的工位（如包装） | 复杂双手作业、新工艺 | 全场景 |

**采用建议**：主线=人拆AI校；AI视频分解留作**6个月后的远期试点**，且只选1类动作幅度大的工位验证，**准入门槛：与人工标注偏差<10%且双手识别准确率>95%才允许扩量**——不达标就停在试点，避免污染刚建好的工时库。

### 2.2 低成本人机协作方案（让入职1~2年的IE做出合格分解）

**① 结构化录入模板（替代自由Excel）**
- 双手双列时间轴布局（左手动作｜动素｜时间 ‖ 右手动作｜动素｜时间），0.5×慢放逐帧录入；
- 要素名称**下拉受控词表**（14类型+子类），禁止自由文本；
- 每要素必填6项：类型 / 手别 / 起点描述 / 终点（分界点）描述 / 时间 / 频率；另有4个**条件必填项**（起始时间戳、动作等级、移动距离、对象物料——见t_element字段表），系统按类型自动带出默认值，人工只改偏离项，单要素新增录入成本控制在10~20秒；
- 变异单元（换料/擦拭）单列，**禁止混进定期单元平均**（偶发被摊薄=标准偏松）。

**② 动素速查表嵌入录入界面**
- 14类型卡片：类型定义 + 1个典型视频截图 + 判断口诀（如"手不动超过1秒=持住H，治具的活"），悬停即看，新人不用翻手册。

**③ AI校验规则引擎（第一优先上线，成本最低、见效最快）**

| 校验类 | 规则示例 | 处理 |
|---|---|---|
| 命名/类型 | 名称不在受控词表；类型与名称逻辑矛盾 | 拦截提交 |
| 时间逻辑 | 单要素<0.1s或>30s；Σ要素时间 vs 循环CT偏差>±5%（查漏/多录）；双手时间轴出现非法重叠 | 红色提示，人工确认 |
| 频率 | 频率字段空缺；变异单元频率>0.5 | 提示补录 |
| 条件必填 | ①双手作业工位未填start_time_offset_ms；②E10/E20/E95/E120未填motion_level；③E20/E120未填move_distance_cm；④E10/E20/E40/E50未填material_id | 草稿不可提交 |
| 完整性 | 缺分界点描述、缺video_id、缺SOP版本 | 草稿不可提交 |
| VA逻辑 | 检验类标NVA、持住标VA | 反向确认提示 |
| 横向比对 | 该要素时间 vs 同类型历史库P50偏离>3σ | 离群提示，复核后可放行 |
| 理论校核 | 实测时间 / MOST理论值 >1.25 | 提示"可能是方法/治具差异，不是人快"（呼应评比纪律） |

**④ 保留录像会审机制**：评比打分场景下IE主管按10%抽审"视频+分解记录"双人会审，既是质量兜底也是新人带教。

### 2.3 视频管理规范

**拍摄标准**：
- 分辨率1080p，帧率30fps（含<1秒快要素的工位用60fps）；固定支架，禁止手持；
- 机位：侧面45°主机位（看双手+时间轴）+ 正面辅机位（看动作方向），覆盖完整作业域；
- 连续拍摄**≥5个稳定循环**，开线30分钟稳定态后再拍，异常处理/试产/缺料期间不拍；
- 视频前3秒拍**工位信息卡**：工位码 / 拍摄日期 / SOP版本 / 操作员等级（老手/新手）。

**命名与关联**：`{line}_{station}_{yyyymmdd}_{sopver}_{take}`，如 `L01_ST10_20250601_SOP3.2_T2`。视频表字段：video_id(PK) / station_code / sop_version / operator_level / cycle_count / 拍摄人 / 时长 / 存储路径 / 授权范围。

**安全与权限**：工时证据视频属敏感数据，按产线授权访问；AI分析默认只使用视频元数据+已录入的结构化分解结果，不做人脸/身份识别。

## 3. 工时数据处理与BOL更新维护（流程步骤3/8）

### 3.1 评比与宽放：人工定值权 + AI辅助

**原则：AI只给参考区间和异常提示，定值在人。**（依据：评比给依据、宽放靠实测——被质疑时拿不出依据，标准当场作废）

AI辅助三件事：
1. **观测充分性检查**：按观测次数公式（目标精度±5%、置信95%）与CV>0.15加测规则，自动提示"循环数不足，建议加测至n次"；
2. **评比辅助**：基于实测/理论（MOST或标准库）比值给建议区间；系数>1.25系统黄灯、>1.30拦截（说明是方法差异不是人快，该改方法）；
3. **异常检测（定值前）**：工位标准工时三方比对——vs 本工位历史P50 / vs 同类工位横向 / vs 理论值，偏差>±15%进入人工复核队列，复核意见留痕后放行。

宽放按**作业强度分档**（轻/中/重）预设档位，参考区间（电子制造典型值，须本厂工作抽样校准）：

| 宽放构成 | 轻作业 | 中作业 | 重作业 |
|---|---|---|---|
| 生理宽放 | 3~5% | 3~5% | 4~5% |
| 疲劳宽放 | 4~8% | 8~12% | 12%+ |
| 事务宽放 | 2~5% | 2~5% | 2~5% |
| 特定宽放 | 按实测构成给 | 按实测构成给 | 按实测构成给 |

**治理规则**：档位值由IE委员会每半年用工作抽样复校一次；单工位宽放偏离所在档位±2个百分点，须IE主管批准并留理由。

### 3.2 BOL版本管理与变更审批流程

**流程（六节点，全线上留痕）**：

| 节点 | 角色 | 动作 | SLA |
|---|---|---|---|
| ① 起草 | IE工程师 | 建草稿版本，系统自动生成版本号+新旧**变更对比diff**（要素级对照表） | — |
| ② 预校验 | 系统 | 规则引擎全量校验（1.4/2.2全部规则），不过不准提交 | 秒级 |
| ③ 审核 | IE主管 | 审数据完整性、评比依据、宽放偏离、变更合理性 | 24h |
| ④ 批准 | ME/制造经理 | 变更影响量>10%或涉及人力配置的，升一级批准 | 48h |
| ⑤ 生效 | 系统 | 默认次日首个班次生效；安全/质量紧急项可即时生效但须72h内补审 | — |
| ⑥ 回溯 | 系统 | 版本链全保留，任一历史时点可导出当时BOL快照 | — |

**触发规则（自动建复测任务）**：ECN工程变更 / 换型 / 治具或来料变更 / 改善实施后复测 / **有效期到期（量产稳定件3~6个月复测）** / CT波动报警，任一触发，缺编号（ECN号或改善案号）不准发版。**复测循环数口径（与SOP模块统一）**：凡用于发版（生成新版BOL）的复测数据≥15个完整循环，CV>0.15加测至≥25——复测数据直接成为新版标准工时，必须满足发版级样本量；允许≤10循环做改善方向快速预判，但预判数据不入库不发版。

### 3.3 企业资产沉淀：动作要素级标准工时库（标准资料法）

**入库机制**：生效满3个月且复测偏差≤±5%的要素 → 自动生成入库候选 → IE抽验10% → 打标签入库。标签三维度：**类型（14类）× 对象特征（重量档/距离档/精度档）× 难度**。

**库结构示例**：`取料-轻件≤50g-距离≤30cm-单手：P50=1.2s，样本n=35，来源线×5，离散度CV=0.08`。

**四个复用场景**：
1. 新品报价：查库加和出工时预估，**必带置信区间与假设条件**（熟练度82BSI、稼动率假设）；
2. 转产/新线预估：MOST补库中缺口类型；
3. AI异常检测基线：横向比对P50的来源就是这个库；
4. 人机协作录入的实时参考（录入时显示"同类要素历史P50=1.2s"辅助新人）。

**治理**：每季度出库健康度报告（样本数 / 离散度 / 类型覆盖率），离散度大的类型优先安排实测补样。

## 4. 落地建议

### 4.1 实施优先级

| 阶段 | 周期 | 交付物 |
|---|---|---|
| **P0** | 0~1月 | 数据结构定稿、编码规则与受控词表发布；1条瓶颈线试点（结构化模板+AI校验规则引擎v1） |
| **P1** | 1~3月 | 校验规则全量上线；版本审批流上线；视频规范落地；双轨迁移启动 |
| **P2** | 3~6月 | 标准要素库v1（首个产品族）；MOST理论值校核模块；迁移切换发版 |
| **P3** | 6月+ | AI视频分解单类工位试点（精度门槛制）；报价查询接口开放 |

### 4.2 必须保留的人工审核点清单（硬清单，8项）

1. 动作分解结果提交前人工确认签字；
2. 评比系数定值（AI只给区间）；
3. 宽放率定值（偏离档位须IE主管批准）；
4. VA/NVA人工覆盖判定（必留理由）；
5. 异常值剔除（必记录原因——默默删数=造假）；
6. BOL发版批准；
7. 改善后工时生效确认（复测数据人工核对）；
8. 标准要素库入库候选抽验（≥10%）。

### 4.3 验证指标

| 指标 | 基线（现状估算） | 目标 | 验证方式 |
|---|---|---|---|
| 数据结构化率（四层完整+受控词表命中） | <10%（Excel自由格式） | ≥95% | 系统自动统计 |
| 单工位BOL更新耗时（步骤1~3合计） | 4~6h/工位 | **≤2h/工位** | 系统工时戳 |
| AI校验低级错误拦截率 | — | ≥80%（提交前拦截） | 校验日志 |
| 生效后30天复测偏差 | — | ≤±5% | 抽测 |
| 评比依据留存率 | ~0 | 100% | 字段非空校验 |
| 发版周期（草稿→生效） | 无流程/数天 | ≤3个工作日 | 流程日志 |
| 标准要素库积累 | 0 | 首族≥200个生效要素（6个月） | 库统计 |
| AI校验误报率 | — | ≤20%（误报太高会被用户关掉） | 复核抽样 |

### 4.4 与下游模块的接口约定

- **线平衡模块（劳永衡）**：`t_station_time_snapshot`（工位级VA/NVA占比+标准工时+瓶颈标记）即山积表数据源，字段设计已兼容，直接调用即可，不需要二次清洗；`manual_ct_s`与`machine_ct_s`分列，直接支撑人机分析的人/机时间拆分；
- **增值分析模块**：以要素层 `element_type + va_class` 为主索引做NVA统计与改善机会识别；
- **改善跟踪模块**：改善案号与 `element_code` 双向关联，改善实施复测后自动生成新版本BOL（闭环步骤8）。
- **SOP模块（苏定标）**：SOP作业步骤表外键=`t_element.element_key`（稳定业务键，不含版本，版本迭代不换键，避免升版断链）；SOP步骤↔标准作业票↔动作要素三表同源联动走"同一变更包"机制——方法变更时SOP变更草案+BOL复测新版**同步发版**（ECN号/改善案号同号关联），只改一头另一头不同步则拦截发版。

**VA/NVA/NVA归类规则单一来源条款（v1.1增补，与线平衡模块协调结果）**：
1. 归类规则的唯一维护点=线平衡分析引擎的**可配置规则表**（动素类型→VA/NNVA/NVA映射+置信度）；数据底座受控词表中的14类型默认VA映射作为**初始基线一次性导入**该规则表，不另设第二套规则；
2. 要素级归类结果（含va_confidence置信度）由分析引擎**回写**要素主表（va_class / va_confidence / va_class_default），人工复核只发生一次、回流只有一个口；工位级占比=要素级汇总，快照表只做汇总与NVA>10%预警，**不做规则计算**；
3. 规则表任何变更须挂**规则版本号**，并触发受影响工位快照重算，变更走留痕审批——否则历史占比不可比、预警口径漂移。线平衡侧规则表配套三个管控字段：`rule_version`（规则版本号）/ `change_log`（变更原因+审批人）/ `affected_station_recalc`（快照重算开关），变更审批与BOL发版同级；
4. 模糊情形（va_confidence<0.8）进入复核队列，复核结论回流后该要素置信度重置为1.0，不再重复复核。初始基线导入时已识别三处默认口径差异点（检验I、设备等待UD、预对PP在两侧默认口径下归类可能不同），统一按置信度=中导入，由复核机制接管——这正是"默认归类+置信度+人工复核"机制的设计意图，不视为冲突。线平衡侧规则表RV 1.0定为**四列结构：要素类型 / 默认归类 / 生效条件 / 置信度**，三处差异点的生效条件注释已对齐（E60"规定检验项→VA，否则NNVA"、E100"节拍设计缓冲→NNVA，否则NVA"、E95保持NVA改善导向），复核人员按生效条件裁决；
5. **P3区间估计口径（已与线平衡侧对齐）**：线平衡模拟山积图直接引用标准要素库条目的预测区间（由样本量n与离散度CV计算，库侧统一供公式），线平衡侧不自算——模拟列、实测复测、对账三处口径统一；展示形式为瓶颈柱带区间须（区间上沿是否超TT一眼可判）。

**要素层四个自动化支撑字段（v1.1增补，决定线平衡模块P2/P3自动化率）**：`start_time_offset_ms`（起始时间戳，双手作业图自动化的开关）、`motion_level`（动作等级1~5，布局浪费触发器）、`move_distance_cm`（移动距离，搬运浪费触发器）、`material_id`（对象物料，供应链类改善关联前提，配套新增t_material物料主数据表）——四字段均为条件必填+系统按类型带默认值，不阻塞P1上线。

**一句话收尾**：这个数据底座建成后，公司第一次拥有"可审计、可回溯、可复用"的工时资产——AI能不能做好增值分析，取决于喂给它的结构化数据干不干净；地基打牢了，后面的人工智能分析才不是空中楼阁。
