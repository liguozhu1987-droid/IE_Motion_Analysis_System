# IE 改善平台：开发进度评估与后续重点难点

> 评估口径：**以代码、路由、页面、表结构、测试为准**，不以文档看板/历史汇报为准。
> 评估方式：只读检查（未运行改动、未提交任何变更）。上一轮 4 个测试文件（`workbench-segment-stop.cjs`、`isolated-harness.cjs`、`isolated-run.cjs`、`db-client.cjs`）的改动**保持未提交、本轮未触碰**。
> 标注约定：凡文档已有事实均标出处路径；凡由代码行为推导、文档未明写的判断，标注**（推断）**。

## 0. 结论先行

- **整体判断**：平台不是"半成品骨架"，而是**主链路已跑通、外围治理与上线条件未闭环**的状态。后端 15 个业务模块均有真实服务实现（无 TODO/桩标记），前端 23 个页面按路由懒加载，AI 三段与视频管线 P0 均有可运行代码与测试。
- **最该补的三件事**：① 视频管线"闭环 + 容量护栏"；② 统一身份认证接入；③ 部署与运维兜底（IIS/ARR + 内网证书 + 告警 SMTP + 审计清理）。
- **最大两个风险**：① 双数据库 + 无 CI + 测试基座未收口，导致"改一处、验不全"（回归风险）；② 内网环境与成本约束（Secure Context 证书、转码算力/磁盘、AI 成本）尚未定稿，上线体验与稳定性不可预测。

### 2.2 逐条说明

**A1 统一身份认证（最大一条"已定未做"）**

- 已定方案：Keycloak 作为统一身份提供者 + `CN_AME_SSO_*` 中央人员事实来源 + OIDC 授权码流 + **认证后仍签发本地凭证**（下游鉴权零改动）；OTK 60 秒单次消费避免 Token 进 URL。
- 落地现状（交底书）：SSO 五表 + 种子 + 授权已落库；MSIA / BOL 两系统已完成 OIDC 改造并通过全量测试；**本 IE 平台不在已改造名单内**。
- 本仓库证据：`app/api/src/modules/users`、`app/api/src/auth` 中只有本地账号/JWT 体系（`passport-jwt`、`bcryptjs`，见 `app/api/package.json`），无 OIDC discovery、无 JWKS 验签、无 OTK。
- 结论：**IE 平台接入统一身份认证是"从零开始"，不是开关切换**。交底书里的双轨开关表不适用于本系统（推断：交底书只覆盖 MSIA/BOL）。

**A2 部署**

- `docs/deployment/DEPLOY-CONFIG.md` 已定：IIS + ARR 反代（HTTPS 443 → Node `127.0.0.1:3001`）、AD CS 内网证书解决 Secure Context、`VIDEO_MAX_MB=2048`、IIS `maxAllowedContentLength` 的 413 坑、HSTS 仅 HTTPS 开启、验证清单含 `window.isSecureContext === true`。
- 代码侧：无 `web.config`、无 IIS 部署脚本产物；仓库根无 `package.json`（仅 `app/api`、`app/web` 各自一份），无统一构建/发布入口。
- 结论：**部署方案已定稿、工程化未落地**。

**B 组未决项的阻塞关系**

- 第 19 行（算力/磁盘预算）直接卡住 `VIDEO_DERIVED_MAX_GB` 配值与 LRU 阈值 → 上线容量不可控。
- 第 20 行（视频是否可上传代理）影响"车间共享视频"能否进入服务端派生链路 → 影响视频模块的产品边界。
- 第 21 行（Tauri）是证书路线失败时的 Plan B，未定不影响主路径，但会在内网证书延期时变成阻断项。
- 第 24 行（断点续传）是 backlog，不阻塞上线，仅影响大文件体验。

**C 组易误判项**

- `docs/specs/` 下实际只有 `SPEC-VID-P0.md` 一个文件；另有根目录 `docs/Spec-AI-动作切分-v1.0.md` 与三份 ADR（`ADR-VID-001`、`ADR-AI-SEG-001`、`ADR-AI-SEG-002`）。**不要把 `deliverables/` 下的历史设计稿当成现行规格**——它们多数是 2026-10 的设计方案，未标注"已实现/已废弃"状态（推断：无状态字段）。
- `OPEN-DECISIONS.md` 头部当前为 **4 未决 / 12 已决 / 2 已关闭（转入 Spec）**，与用户给定口径一致。

## 3. 后续开发重点（按产品哲学排序）

排序原则：**帮 IE 更快看出问题 → 留；帮管理层管住 IE → 砍**。

### P0（不做就不能"上线可用"）

| 优先级 | 事项 | 目标 | 涉及层 | 验收口径 |
|---|---|---|---|---|
| P0-1 | **视频管线闭环 + 容量护栏** | 上传 → 分片合并 → 派生（proxy/sprite/index/keyframes）→ 工作台可播可拖 → 磁盘不失控 | 前端（工作台载入触发 derive、派生状态提示）、后端（`videos`/`derivative`/`derivative-worker`）、运维（ffmpeg/QSV、磁盘配额） | ① 10 条 30min 视频连续上传派生成功率 100%；② 派生失败可重试且 `retry<2` 自动重入；③ `VIDEO_DERIVED_MAX_GB` 配到实测值后，超限触发告警 + LRU 淘汰 proxy 且源视频保留；④ 分片中断 24h 后目录被清理 |
| P0-2 | **统一身份认证接入** | 登录入口统一、离职即失效、审计可归因到人 | 前端（登录页增加 SSO 入口、回调页）、后端（OIDC 客户端 + 身份解析 + 本地凭证签发 + OTK）、数据库（`CN_AME_SSO_UserMap` 映射本系统用户名）、运维（证书/DNS/`CN_AME_SSO_*` 授权） | ① `/api/auth/config` 能返回 OIDC 开关；② 至少 1 名真实 AD 用户走通"授权码 → OTK → 本地登录态"；③ 中央 `status=0` 后本地账号不可登录且存量 Token 失效；④ 双轨期本地登录仍可用 |
| P0-3 | **部署上线链路落地** | IIS/ARR + 内网证书 + Secure Context + 上传上限 | 运维（IIS、ARR、AD CS 模板/GPO）、后端（启动参数、端口、HSTS 条件）、前端（能力探测降级） | ① `https://<内网域名>` 打开，`window.isSecureContext === true`；② 大文件上传不触发 413（分片路径生效）；③ Node 仅监听 `127.0.0.1:3001`，外部不可直连；④ HTTP 访问被重定向到 HTTPS 且无混合内容告警 |
| P0-4 | **告警 SMTP 落地 + 业务告警最小集** | 出问题第一时间有人知道 | 后端（`core/alert` 扩规则、`mailer.service`）、运维（SMTP 参数） | ① `SMTP_HOST` + `ALERT_MAIL_TO` 配置后，手动触发登录锁定规则能收到邮件；② 新增 3 条业务规则（派生失败率、AI 任务失败率、派生磁盘占用）并各有触发/恢复日志；③ 冷却窗口内不重复刷屏 |
| P0-5 | **双手双轨时间线补齐** | 全 `B` 要素也能进入双手图与平衡分析 | 前端（工作台拆手交互）、后端（`engine.ts` 双手图口径）、数据库（要素手别字段语义） | ① 全 B 片段可一键"拆分为左右手"并落库；② 拆分后 `handsChart` 左右手时序不重叠、总时长守恒；③ 未拆分时分析页给出明确提示而非静默退化 |

## 4. 难点

### 4.1 技术难点（难在实现）

| 难点 | 为什么难 | 当前可行路径 | 卡在谁身上 |
|---|---|---|---|
| **MSSQL + SQLite 双轨** | 方言差异实锤：`MERGE ... SYSUTCDATETIME()` 在 SQLite 不可用（上一轮 `acl-read-guard` 17 条失败即此因）；`desc` 保留字需 TypeORM 自动转义（`element.entity.ts` 注释） | 已走通一条路：**吃方言的套件指向专用 MSSQL 测试库，其余继续 SQLite**（`isolated-harness.cjs` 的 `datasource` 选择 + `ISO_MSSQL_*`）；无测试库时 SKIPPED 而非 PASS | 开发（代码分轨）+ IT（提供专用测试库与账号） |
| **视频时间基准漂移** | 时钟 `video.currentTime` 可领先呈现帧 1 帧（33.3ms），产品按 `metadata.mediaTime` 停帧；测试若用时钟断言必然偶发失败 | 已定位并最小修复（`workbench-segment-stop.cjs` 改用最后一条 `frames` 的 `media_time_ms`，保留 40ms 阈值）；12/12 通过 | 开发（已完成，待确认提交） |
| **ffmpeg 派生并发与磁盘** | 50 并发纯 libx264 队尾约 54min；每 10min 视频 400–750MB，50 人×5 条≈100–190GB（`OPEN-DECISIONS.md` 第 19 行） | 已有 QSV 优先 + 上传后预热 + LRU 删代理保源 + `VIDEO_DERIVED_MAX_GB` 告警的代码骨架；缺实测参数 | 用户（预算）+ IT（核数/磁盘） |
| **无 CI、单实例限流** | 所有校验靠本地脚本；限流/缓存/告警状态在进程内（`auth.service` 的 `setInterval` 桶清理、`alert-monitor` 的 `firing` 状态），多实例即失效 | 单实例部署 + `test:isolated` 全量入口是正确的当前解；扩多实例前需把状态外置 | 运维（是否多实例）+ 开发（状态外置改造） |
| **测试夹具与隔离** | 历史套件依赖固定夹具（如 L01-ST01）、会碰正式库、需外网 | 已实现临时 SQLite/临时 cwd/随机端口/环境强制/每轮清理/残留基线；遗留：`test-dw-isolation-guard.cjs` 未迁、前端老 UI 套件未纳入 | 开发（迁移排期） |
| **派生存孤儿** | 源文件删除后派生行不级联（`video-derivative.entity.ts` 注释明确 P0 由清理脚本/管理员顺带处理） | P0 接受脏数据；P0.5 加级联或定时对账 | 开发（排期） |

### 4.2 领域难点（难在口径/业务判断）

| 难点 | 为什么难 | 当前可行路径 | 卡在谁身上 |
|---|---|---|---|
| **VA 归类口径** | 规则 + 例外 + 人工改判三层，规则版本已到 RV3.64；同一动作不同 IE 可能判不同 | 已有"人工改判标记"与规则发布链路，保留改判痕迹可追溯；每次规则更新需回归 smoke 的 VA 改判用例 | IE 专家（口径）+ 开发（回归） |
| **双手/双轨语义（全 B 拆手）** | 现场很多动作是"双手同时"，但平衡分析必须分左右；拆手的 IE 语义（同时动作算 1 次还是 2 次、时长如何分摊）无统一标准 | 代码已有 `'L'\|'R'\|'B'` 三值与三轨 UI；缺的是"拆分规则"的产品定义 | IE 专家（定义）+ 产品（交互） |
| **"止点"语义** | MediaPipe 只能给 21 点/手，止点靠速度阈值 + 静止持续帧数近似；与 IE 认可的止点存在系统性偏差 | ADR-AI-SEG-001 已用探针实跑确认"候选止点"路线；定位为候选、人工确认 | IE 专家（验收样本）+ 开发 |
| **平衡率/瓶颈口径** | 代码只有 `total/(maxCt*lineRows.length)` 与"最大 CT 即瓶颈"；真实产线有并行工位、共享设备、换型损失 | 先保持与 MVP 逐字一致，避免口径漂移；新增口径必须以 ADR 形式落地 | IE 专家 + 产品 |
| **收益估算口径** | ComparePage 有年化收益公式与 `settings:benefit-write` 参数，但收益分摊/折旧/稼动率假设未固化 | 参数化 + 展示公式（已做）；需补"假设可审计"（推断） | 财务/IE + 产品 |

### 4.3 成本 / 环境难点

| 难点 | 为什么难 | 当前可行路径 | 卡在谁身上 |
|---|---|---|---|
| **内网与 Secure Context** | `ap.inalfa.local` 是 `.local` 内部 AD 域，公共 CA 不可行（`OPEN-DECISIONS.md` 第 18 行已定 AD CS）；无证书则 WebCodecs/摄像头不可用 | 已选 AD CS 内部 CA；`DEPLOY-CONFIG.md` 给出 IIS+ARR+证书验证清单 | IT（CA 签发）+ 运维 |
| **Keycloak 版本约束** | SQL Server 2017 不支持 `OPTIMIZE_FOR_SEQUENTIAL_KEY`，26.x 回退到 25.0.6（交底书） | 25.0.6 已部署；风险是后续升级受限 | IT + 架构 |
| **AI 成本** | 用户对 AI 视频分析高成本敏感（`OPEN-DECISIONS.md` 第 10 行）；`AI_ENABLED=false` 是当前默认 | 三段 AI 均有配额/限额/缓存/503 降级 + "AI 不产数字"铁律降低成本与错误；切分走浏览器端 MediaPipe，零服务端算力 | 用户（预算）+ 产品（灰度范围） |
| **代理/离线分发** | 实测源站经代理约 12KB/s；模型 hand 7.82MB / pose_lite 5.78MB | 模型随包落 `app/web/public/models/`（7.8MB `hand_landmarker.task` + wasm 13.5MB），禁运行时拉 CDN | 开发（包体控制）+ 运维（首次加载带宽） |
| **无统一构建入口** | 仓库根无 `package.json`，构建/发布需分别进 `app/api`、`app/web`；无 `web.config` | 现有 `app/api` 脚本（`build`/`start`/`migrate:prod`）可用；需补根级编排脚本与 IIS 配置模板 | 开发（工程化） |

## 5. 建议的里程碑切分

> 不给日期，只给"还差什么 + 用工时/依赖表述"。

### M1 上线可用（内部试点，1–2 条产线）

**还差：**

- 视频管线：`VIDEO_DERIVED_MAX_GB` 按实测配置 + 派生失败重试观测（**依赖 IT 提供服务器核数/磁盘 → 才可估工时**）。
- 部署：IIS/ARR 配置、AD CS 证书签发（**外部 IT 依赖，工期不由开发控制**）、`web.config`、根级构建脚本（开发约 1–2 人日，推断）。
- 告警：SMTP 参数落 `.env` + 3 条业务规则（开发约 2–3 人日，推断）。
- 双手全 B 拆手：交互 + 落库 + 分析口径（开发约 3–5 人日，推断；**依赖 IE 专家给拆分规则**）。
- 测试：`workbench-segment-stop.cjs` 等 4 个文件改动确认提交，恢复可信基线（约 0.5 人日）。

**放行标准：** 核心路径（上传 → 分解 → 分析 → 建议 → 对比）在 IE 真实工位上跑通一轮，且断网/断电重来不丢数据。

### M2 可推广（多产线 / 多工厂）

**还差：**

- 统一身份认证：OIDC 客户端 + 身份解析 + OTK + 本地凭证签发（**估 5–8 人日**，推断）；依赖 Keycloak 上线 + `CN_AME_SSO_UserMap` 映射登记（外部依赖）。
- 权限与账号生命周期：SSO 停用回写、本地 Token 清理（约 2 人日，推断）。
- AI 受控开启：配额/成本口径对齐 + 灰度开关（约 3 人日，推断；依赖用户定预算）。
- 审计：定时清理 + 全局检索 + 导出（约 3 人日，推断）。
- 测试基座收口：前端老 UI 套件迁入隔离入口（约 5–8 人日，推断，套件多且历史包袱重）。
- 端到端对比导出改服务端 PDF（约 2–3 人日，推断）。

**放行标准：** 新产线接入无需开发介入（管理员自助建线/建工位/配权限），离职账号当日失效。

### M3 完善（体验与治理）

**还差：**

- 驾驶舱"问题导向"改造（约 5 人日，推断）。
- 断点续传/并行分片（**依赖用户是否接受当前体验**；若做约 5–8 人日，推断）。
- 多版本趋势、跨工位对比（需求未确认，先做最小版）。
- 派生存级联清理/对账任务（约 2 人日，推断）。
- 多实例化前提改造（进程内状态外置；仅在确有多实例需求时启动）。

**放行标准：** 变更可被全量自动化验证覆盖，运维有告警与审计双闭环。
