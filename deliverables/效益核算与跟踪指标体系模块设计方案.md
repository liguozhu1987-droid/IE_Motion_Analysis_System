## 口径确认清单（本方案全篇生效，开发时按此落库）

| # | 口径项 | 定义（锁定版） |
|---|---|---|
| 1 | 标准工时ST | t_element标准工时字段，= 正常时间×(1+宽放率)，带版本号 |
| 2 | 有效工时/人·日 | 出勤工时×(1−宽放率)；年有效工时 = 年出勤×(1−宽放率)，示例取1,900h |
| 3 | 基线（Baseline） | 改善前BOL版本快照（t_station_time_snapshot@v_pre），系统自动锁定，禁止回改 |
| 4 | 复测值 | 措施生效30天后按毕准时口径复测，偏差≤±5%取新快照v_post |
| 5 | 实测节省 | v_post与v_pre的差值，不是理论预计值；预计值仅用于PI排序 |
| 6 | 人力口径 | 直接人力DL+间接人力IDL分列；MDL人力分配表为唯一人力证明来源 |
| 7 | 费率 | HR官方全成本费率（含社保福利等），费率表带取数依据与更新日期，每年1月/7月刷新 |
| 8 | 产出口径 | 当量产量 = Σ(各机型产量×该机型全线ST)，跨机型对比必须用当量，禁用自然件数 |
| 9 | 节约年度 | 按财年，年化 = 月度×12；跨财年项目分段计 |
| 10 | 落地率 | 报数统一按70%落地率折减（报保守不报满，手册铁律） |

## 一、改善效益核算口径设计

### 1.1 结论先行

1. **换算链四步走**：单循环节省秒数 → 全线人力节省（HC）→ 年化节约金额 → Hard/Soft/NWC分类入账。跳步换算（秒直接乘费率）一律无效。
2. **Hard/Soft的分水岭只有一条**：钱是否真的进了营业利润（OP）。工时省了但人没动、产能空着没单，都是Soft。
3. **财务认可三件套**：官方费率表 + 七要素计算书 + 四级签认证据链。月度节约>阈值（建议1万元人民币，参照手册1,000美元门槛）必须过财务验证。
4. **预计≠实绩**：所有对外报数用实测节省（v_post−v_pre），预计值只留在建议清单做排序和达成率分母。

### 1.2 换算公式表（可直接进开发需求文档）

| 步骤 | 公式 | 字段来源 | 说明 |
|---|---|---|---|
| ① 单站循环节省 | ΔST站 = ST站@v_pre − ST站@v_post | t_station_time_snapshot | 同要素集对比；ECN引起的要素增删要剔除（那是设计变更不是改善） |
| ② 全线单件节省 | ΔST线 = ΣΔST站（重平衡后口径） | 快照表汇总 | 需经劳永逸的平衡模块重排后取新编成方案 |
| ③ 人力节省 | ΔHC = ΔST线(h) × 日产出需求(件) ÷ 每人日有效工时(h) ÷ 目标达成率(95%)，结果向下取整 | 快照表+排产+MDL | 产线人数是整数且受最少编成约束；减员路径按手册铁律：先自然流失不补→多能工并线→再排布优化 |
| ④ 年化Hard节约（人力类） | 年化 = ΔHC × 年有效工时(1,900h) × DL全成本费率 | MDL+费率表 | 人转岗/顶替流失补员仍算Hard（手册细则1） |
| ⑤ 产能型节约（需求充足） | 年化 = 年增量产出 × 单件人工成本节省额；或避免的加班费/外发加工费/新增线人力成本 | 排产+费率表 | 免加班、免新增班次：实际不发生的支出=Hard |
| ⑥ 产能型（需求不足） | 理论工时价值，**计Soft** | — | 产能空间≠现金，财务不认Hard |
| ⑦ 工程师工时节约 | Σ(改善前耗时−工具耗时)×IDL费率×再投入有效系数(60%) | 工具埋点日志 | 属Soft潜能，工具ROI测算专用口径（见第三章），不进精益节约账 |
| ⑧ 平衡率收益 | 平衡率 = Σ各站ST ÷(瓶颈站ST×站数)，目标≥85% | 快照表 | 平衡率提升本身是过程指标，变现仍走③④ |
| ⑨ UPH理论提升 | ΔUPH% = (3600÷CT_new)÷(3600÷CT_old)−1，仅计瓶颈路径节省 | 快照表 | 非瓶颈站节省不直接提UPH（全线速度被最慢站锁死），只能进人力再分配 |

### 1.3 Hard / Soft / NWC判定表（按本工具建议类型映射）

| 建议落地结果 | 判定 | 判定证据 |
|---|---|---|
| 减员且人员转岗/顶替流失补员 | **Hard** | MDL前后对比+HR在编数据 |
| 减班次/免加班，加班费实际下降 | **Hard** | 考勤加班工时前后对比 |
| 需求增长下免新增线/免新增HC | **Hard** | 产能测算+排产记录（避免了的投资） |
| 省工时但HC未变、无加班削减 | **Soft** | MDL无变化 |
| 良率/报废改善，报废金额实际下降 | **Hard** | 品质报表+单价 |
| WIP/库存下降带来利息或外仓费下降 | **Hard**；仅理论持有成本=**NWC** | 财务口径 |
| 空间腾出被其他项目接收/整栋退租 | **Hard**；厂内闲置=**Soft** | 租赁合同/项目接收单 |
| 工程师分析时间节省 | **Soft**（工具ROI另算） | 工具日志 |
| 纠错性恢复（修回自己搞坏的状态） | **不算节约（红线）** | — |
| 供应商议价降价 | **不算精益节约（红线）** | — |

### 1.4 证据链与财务验证流程（系统工作流固化）

**每笔节约四件套（缺一不生成节约记录）：**
1. **基线快照**：v_pre自动锁定（版本号、锁定日期、取数人），不可回改；
2. **复测数据**：生效30天复测报告（毕准时±5%口径），复测人、日期系统留存；
3. **人力/资源证明**：MDL前后对比、考勤加班数据、报废报表等对应类目数据源；
4. **签认链**：提案人→产线主管→IE主管→财务（月度>1万元强制），系统电子签认流。

**计算书七要素（自动生成，人工只补充说明）：**
当前月度成本 / 改善后月度成本 / 月度节约 / 节约% / 实施日期 / 实施日至财年末累计 / 年化节约。

**流程节奏**：分批滚动提交（不攒月底），避开财务结账期；争议由财务总监+总经理终裁。低于1万元门槛由IE主管自行验证，同样留四件套。

## 二、三层跟踪指标体系

### 2.1 工具运营KPI（衔接劳永逸验证指标，补充4项）

| 指标 | 定义公式 | 目标值 | 数据源 |
|---|---|---|---|
| 分析耗时达标率 | 达标次数÷总分析次数（工位级≤5min/全线≤30min/建议清单≤10min） | ≥95% | 工具埋点 |
| 建议采纳率 | 人工采纳条数÷系统生成条数 | 首年≥50% | 建议清单 |
| AI误判率 | 人工审核驳回条数÷生成条数 | ≤8%（P1）→≤5%（P2） | 审核日志 |
| 规则覆盖率 | 规则引擎可判定要素数÷要素总数 | ≥90% | 规则引擎日志 |
| **BOL更新及时率（补充）** | 按期完成更新的工位数÷应更新工位数 | ≥90% | t_element版本 |
| **复测偏差合格率（补充）** | 偏差≤±5%的复测数÷复测总数 | ≥85% | 复测报告 |
| **建议-实施转化周期（补充）** | 中位数：建议生成→实施完成的间隔天数 | ≤45天 | 建议状态流 |

### 2.2 改善项目KPI

| 指标 | 定义公式 | 目标值 | 告警线 |
|---|---|---|---|
| 建议实施率 | 已实施÷已采纳 | ≥75% | <60% |
| 建议关闭率 | 已验证关闭÷已实施 | ≥90% | <75% |
| 逾期率 | 超计划完成日未关闭÷实施中 | ≤15% | >25% |
| **实际节省验证率** | 实测节省÷预计节省 | 85%~110% | >120%（预测模型失准，复盘PI参数）或<70%（实施质量存疑） |
| PI预测准确性 | 预计节省vs实测的MAPE | ≤30% | — |
| Hard节约月度金额 | Σ已验证Hard节约（按1.2公式④⑤） | 按年度目标分解 | 进度<时序80% |
| 财务验证通过率 | 财务签认÷提交验证数 | ≥90% | <80%（口径要复盘） |

### 2.3 产线人效KPI（防"算法性虚增"是设计核心）

| 指标 | 定义公式 | 对比口径 |
|---|---|---|
| 当量UPH | 当量产量÷直接工时(h) | 同机型或当量口径，声明BOL版本 |
| 平衡率 | Σ站ST÷(瓶颈ST×站数) | v_pre vs v_post快照 |
| VA占比 | ΣVA要素ST÷Σ全部ST | 快照表直接取 |
| 人时产出 | 当量产量÷(DL+IDL)工时 | 含间接人力，只算DL会虚高 |
| 单件人工成本 | ST线(h)×DL费率÷达成率 | 快照+费率表 |
| 人均产出/月 | 当量产量÷(DL+IDL)在编 | HR在编 |

**防虚增三排查机制（异常解读必须逐项过）：**
1. **真改善**：v_post复测通过且MDL/产能数据同向变化 → 认；
2. **结构变化**：产品组合变了 → 用当量产量重算，禁用自然件数；
3. **口径变化**：BOL升版、宽放调整、统计范围变化 → 声明口径差异，重算基线。
另加**稳定期剔除**：措施上线前后各2周学习曲线期数据不入对比（手册NPI分阶段策略同理）。

## 三、AI工具自身ROI测算框架

### 3.1 结论先行

规则引擎定量+LLM只做文案的架构下，**LLM调用成本可忽略（数量级为每产线每年百元~千元级）**，成本大头是开发投入与运维；收益大头是改善建议落地年化节约，其次才是工程师工时替代。示例测算（10条30工位产线）回收期约**9~11个月**。

### 3.2 成本侧

**分阶段开发成本（结构化估算，进预算前按内部人月单价换算）：**

| 阶段 | 内容 | 工作量估算 |
|---|---|---|
| P1（0~3月） | 规则引擎+数据底座集成+快照/复测/签认工作流 | 10~12人月 |
| P2（3~6月） | LLM建议文案+RAG案例库+仪表盘 | 6~8人月 |
| P3（6~12月） | 人机联作分析+视频AI试点（谨慎，独立立项评审） | 8~10人月 |
| 年运维 | 规则维护、费率表更新、提示词与模型版本管理、数据治理 | 开发成本的15%/年 |

**LLM调用成本估算方法（给数量级，不算死数）：**

> 年LLM成本 = Σ(年调用次数 × 单次token量 × 模型单价)

- 本架构下结构化数据分析全部走规则引擎，**token消耗为零**；LLM只在「建议文案生成」和「RAG案例检索」两个环节出场。
- 单条建议单次调用token量：要素数据摘要2~4K + 案例库上下文3~5K + 输出1~2K ≈ **6~10K tokens**；按主流企业级模型单价（输入/输出混合约$0.5~2/百万token量级）→ **单条建议$0.005~0.02**。
- 单工位一轮分析约15条建议 → $0.1~0.3/工位；30工位产线年4轮 → **$12~36/线/年**；叠加月报异常说明草稿（每月每线约50K token）→ 合计**每线每年LLM成本百元人民币以内到小几百元**。
- 风险对冲条款：LLM调用设月度token上限熔断，超限自动降级为模板文案。

**运维成本**：约=开发总投入×15%/年 + LLM成本（可忽略）+ 1名兼职数据治理（0.2 FTE）。

### 3.3 收益侧（两个来源，口径不同不许混）

**A. 工程师分析工时替代（工具ROI专用，Soft口径）：**

| 工作项 | 改善前 | 工具后 | 单次节省 |
|---|---|---|---|
| 单工位VA/NVA分析 | 2~4h | ≤5min | ~2.5h |
| 全线平衡诊断 | 2~3天 | ≤30min | ~16h |
| 单工位BOL更新 | 4~6h | ≤2h | ~3h |

按1条30工位线年4轮全线诊断+每工位年2次更新：4×16 + 30×2×2.5 + 30×2×3 = **约400h/线/年**。乘再投入有效系数60%（省下的时间须真实投入改善产出才兑现价值，防虚增）→ 有效240h × IE全成本费率（示例100元/h）≈ **2.4万元/线/年**。

**B. 改善建议落地年化节约（Hard为主）：**

示例参数（保守）：30工位线、DL 30人、DL全成本费率25元/h、年有效工时1,900h；年生成建议60条/线，采纳率50%→30条，实施率75%→22条，验证通过后全线年化工时节省按4%计（手册平衡与动作路径典型收益10~20%的保守折减）：
- ΔHC ≈ 30人×4% ≈ 1.2人，取整并按自然流失路径落地 ≈ 1人 → Hard年化 ≈ 1×1,900×25 = **4.75万元/线/年**
- 加免加班/良率类Soft约2万元/线/年 → 合计约**6.75万元/线/年**，再按70%落地率报数 ≈ **4.7万元/线/年（报保守值）**

### 3.4 ROI示例测算与结论

| 项目 | 数值 |
|---|---|
| 覆盖范围 | 10条产线、5名IE |
| 一次性投入 | P1+P2开发约18人月×3万元 = 54万元（P3视频试点单独立项，不计入） |
| 首年运维 | 54×15% ≈ 8万元 + LLM约0.2万元 |
| 年收益（保守） | 工时替代10×2.4=24万 + 改善节约10×4.7=47万 ≈ **71万元/年** |
| **回收期** | (54+8)÷(71−8) ≈ **0.98年 ≈ 12个月** |
| 首年ROI | (71−8)÷62 ≈ **102%** |

**敏感性分析（必须附）：**

| 情景 | 回收期 |
|---|---|
| 基准（采纳率50%） | ~12个月 |
| 悲观：采纳率30%、工时节省减半 | (62)÷(24×0.6+4.7×10×0.6−8) ≈ 62÷34 ≈ 22个月（仍<2年，可行） |
| 乐观：采纳率70%、收益按实测值（不打7折） | ~7个月 |
| 只上P1不上P2 | 投入约36万，收益约52万/年 → 回收期~9个月（P2的增量ROI为正，建议分闸门决策） |

## 五、人效月报自动生成机制

### 5.1 生成流程（每月1日自动跑批）

```
考勤系统 + MES产量 + t_element快照 + 建议清单 + MDL
        │  （自动取数，口径按第一章锁定）
        ▼
  指标计算引擎（规则引擎，零token）
        ▼
  八栏月报初稿 + 异常标记（规则触发）
        ▼
  LLM生成「异常说明」草稿（引用数据，人工必审）   ←唯一LLM环节，月每线~50K token
        ▼
  IE主管审核（预计≤30分钟/成本中心）→ 电子签发 → 分发
```

### 5.2 月报模板（八栏，成本中心维度拆分）

每指标固定八栏：**当月值 / 上月值 / 环比 / 去年同期 / 同比 / 目标 / 达成率 / 异常说明**。

| 指标块 | 指标 | 数据源 | 生成方式 |
|---|---|---|---|
| 产线人效 | 当量UPH、平衡率、VA占比、人时产出、单件人工成本 | 快照+MES+MDL | 全自动 |
| 改善跟踪 | 建议实施/关闭/逾期、Hard/Soft月度节约、验证率 | 建议清单+节约台账 | 全自动 |
| 工具运营 | 分析耗时、采纳率、误判率、LLM成本 | 工具埋点 | 全自动 |
| 异常说明 | 按三排查（真改善/结构/口径）预分类+LLM草稿 | 全部 | **人工审核**（唯一必审环节） |
| 下月计划 | 逾期清单+高PI待实施建议 | 建议清单 | 自动列出，人工补充 |

### 5.3 成本中心映射

产线编码→车间→成本中心三级映射表由IE维护、系统固化；月报按成本中心拆分汇总，与财务月结口径对齐（费用科目：直接人工/制造费用分列，避免与财务打架）。

### 5.4 人工环节（仅三处，总耗时≤1h/月/成本中心）

1. 异常说明审核（LLM草稿改错+补充现场信息）；
2. 口径例外确认（月中换版/换型的产线标注）；
3. 签发。
