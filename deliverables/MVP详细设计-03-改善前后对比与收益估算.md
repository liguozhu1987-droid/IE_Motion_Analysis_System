## 1. 复测全流程状态机

### 1.1 状态推导规则（零新增表）

不建状态机表，工位分解状态由 `t_station.version`（当前生效版本号 V）与 `t_element.bol_version` 推导：

| 状态 | 推导条件 | 数据特征 | 允许的操作 |
|---|---|---|---|
| S0 分解生效 | 存在 bol_version=V 要素且已通过3条校验 | t_station.version=V 可编辑 | 编辑要素、分析、生成建议、**点"开始复测"** |
| S1 复测中（草稿） | 存在 bol_version=V+1 要素（未提交/校验未过） | v(n)=V 自动锁定只读（封存即生效，无需额外标志：version 一推进，旧版天然只读） | 在分解工作台录入新分解；**不可再点"开始复测"**；可"作废本次复测" |
| S2 新版生效 | v(n+1) 提交且3条即时校验全部通过 | 系统自动：①重算 t_station.CT=Σ生效非异常要素ST ②updated_by/updated_at 刷新（封存与version推进已在"开始复测"点击时完成——与01§8定稿一致：点击即推进version=V+1，旧版因指针移开天然只读；本行不再重复推进version） | 对比页解锁；提示回填建议状态 |
| S3 对比可用 | t_station.version≥2 且 v(n-1)、v(n) 两版要素齐全 | 前后两版均只读（除最新版可编辑） | 查看对比、生成/导出报告 |

- **封存=只读的实现**：所有写操作仅允许作用于 `bol_version = t_station.version` 的要素；旧版任何字段拒绝写入，无例外。
- **作废复测**：删除 v(n+1) 草稿要素 → v(n) 自动恢复为可编辑当前版。封存不是失效，只是只读。

### 1.2 "开始复测"触发条件（定稿）

| # | 条件 | 类型 | 规则 |
|---|---|---|---|
| 1 | 该工位存在 ≥1 条 `t_improvement.status="已完成"` 的建议 | **推荐条件** | 命中→按钮正常可用；未命中（全为"待实施"）→ 弹提示"当前无已实施改善建议，确认仍要复测？"，IE可继续（口头改善未录建议属正常场景） |
| 2 | 无进行中的复测草稿（不存在 bol_version>version 的要素） | 硬拦截 | 命中→按钮置灰，提示"已有复测进行中，请先提交或作废" |
| 3 | 当前生效版数据完整（3条校验通过态） | 硬拦截 | 未通过→提示先修复当前分解再复测 |

**定稿结论**：以"建议已实施"为推荐触发、以数据完整性为硬拦截，不做强制天数间隔（学习曲线稳定期仅作提示，见 §7）。

### 1.3 复测完成后的闭环动作（顺序固定）

1. v(n+1) 通过3条即时校验（必填完整性/时间轴重叠/循环数<15）→ 提交生效（S2）；
2. 系统自动回填 `t_improvement.before_ct = CT@v(n)`、`after_ct = CT@v(n+1)`（仅对该工位 status="已完成"的建议）；
3. 对比页展示前后对比 → IE人工确认后将建议置 `status="已验证"`（**AI只建议不执行，状态切换必须人工点击**）；
4. 收益估算行在参数已配置时同步显示（见 §4）。

## 2. 前后要素配对算法（核心难点）

改善后要素结构会变（删/增/合并/拆分），配对分三层，逐层降级：

### 2.1 匹配层级与规则

| 层 | 规则 | 判定档位 |
|---|---|---|
| L1 建议精确关联 | 前版要素 ∈ 某 `t_improvement.element_ids` → 标记为"改善目标要素"；若该建议方法为消除/合并类（E/C），其在后版**无对应物属预期结果**，直接判"改善消除"，不算配对失败 | 消除（绿色收益） |
| L2 同type+desc相似 | 其余要素先按 type（10类）分组，组内：①desc 归一化（去首尾空格、全半角统一）完全相等 → **匹配成功**；②编辑距离相似度 ≥0.75 → 匹配候选；③0.60~0.75 → **部分匹配**（需人工在对比页一键确认或改配） | 成功/部分 |
| L3 seq邻近兜底 | 同 type 且前后 seq 差 ≤2 且未与其他要素强匹配 → **部分匹配**，界面标注"按位置推断，请确认" | 部分 |

相似度 = 1 − 编辑距离 ÷ max(len前, len后)，中文按字符计算，纯前端实现，不引库（Levenshtein 约20行代码）。

### 2.2 三档定义与对比表展示

| 档位 | 定义 | 对比表展示 |
|---|---|---|
| 匹配成功 | L1找到对应物（同type同desc）或 L2-①/② | 双行并排：前ST → 后ST，差值着色（节省绿/增加红） |
| 部分匹配 | L2-③或L3推断，未经人工确认 | 同上但黄色底+「待确认」角标，人工确认后转绿；未确认不计入要素级节省 |
| 未匹配 | 仅存于前版 →「消除」（若属L1改善目标则记改善成效，否则提示"疑似ECN/漏录"）；仅存于后版 →「新增」（默认计负贡献冲减节省；IE可勾选"属设计变更"剔除该负贡献） | 单行显示+来源标注 |

### 2.3 配对率与降级阈值（定稿）

- **配对率** =（匹配成功数 + 已确认部分匹配数）÷ min(前版生效要素数, 后版生效要素数)；异常要素（outlier_flag=1）先剔除再算。
- ≥80%：正常要素级对比；60%~80%：要素级对比+顶部黄色横幅"要素结构变化较大，节省秒数建议以工位级为准"；**<60%：降级为工位级对比**（隐藏要素明细表，只展示 CT/VA占比/浪费统计/收益行，均用工位级口径），并注明降级原因。
- 示例：前版12要素、后版9要素（合并2取放为1、消除持住1、其余匹配9）→ 匹配9+消除预期1=10 ÷ min(12,9)=9... 分母取9 → 配对率100%（预期消除不算失败）。若乱序重录致只匹配4条 → 4÷9=44% <60% → 降级。

## 3. 节省秒数口径

### 3.1 两级口径

| 级别 | 公式 | 说明 |
|---|---|---|
| 工位级（权威口径） | ΔCT = CT@v(n) − CT@v(n+1)；CT = Σ生效且非异常要素 std_time（蓝图补丁3） | 配对率<60%时**唯一**口径；收益估算默认取此 |
| 要素级（归因口径） | ΔST要素 = Σ(前版配对要素ST) − Σ(后版配对要素ST) + Σ消除要素ST − Σ新增要素ST（剔除设计变更后） | 用于定位每条改善贡献；人工未确认的部分匹配不计 |

- **归因到建议**：消除/配对差中属于 `t_improvement.element_ids` 的部分归到该建议名下（est_save_s 预计 vs 实测并排显示）；跨工位项目按要素归属自然拆分，不做分摊系数。
- **异常要素处理**：前后两版均剔除计算、但**单列显示**"前版异常N条（原因）/后版M条"；后版异常率>20%时提示"复测数据质量存疑，建议补测"。
- **多工位合计**：项目节省 = Σ各工位ΔCT。这是单件产品全线工时节省口径，各工位可直接相加、不重复计算；但报告须注明：非瓶颈工位的节省不提升UPH/产能，仅释放人力工时（MVP一行公式即人力工时口径）。
- **负节省（复测变慢）**：单工位ΔCT<0 → 红色显示"恶化，建议复核复测条件（机型/人员/节拍）"，**不截断不改号**；多工位合计允许正负抵消报净值，但明细行必须逐工位列示，禁止只报总和。

## 4. 收益估算公式与参数配置

### 4.1 公式（固定不可改，蓝图补丁4）

```
年化收益(元/年) = 节省秒数(s/件) × 日产量(件/日) × 365(日) × 综合费率(元/h) ÷ 3600 × 70%
```

示例：节省3.5s/件 × 1200件/日 × 365 × 45元/h ÷3600 × 0.70 = **13,413.75 元/年**。

### 4.2 参数配置表

| 参数 | 含义 | 单位 | 默认值 | 来源 | 维护人 | 存储 |
|---|---|---|---|---|---|---|
| rate_yuan_per_hour | 综合费率（DL全成本+制造费用综合分摊的全成本口径） | 元/工时 | **无默认** | IE主管与财务口头对齐后手填 | IE主管（一次性） | config/benefit_params.json（按line_id一条：`{line_id, rate_yuan_per_hour, daily_output, realization_rate:0.70, configured_by, configured_at}`） |
| daily_output | 日产量 | 件/日 | **无默认** | 最近30天MES实际平均日产量 | IE主管 | 同上 |
| realization_rate | 落地率 | — | **0.70（锁定只读）** | 手册铁律"报保守" | 不可改 | 同上 |

**存储定稿**：不新增表 → 用 JSON 配置文件（蓝图第5节"规则表用JSON文件维护即可"同理），后端读写、对比页"参数设置"入口维护；configured_by 记录最后修改人。**不存 t_station 扩展字段**（费率是线级参数，塞工位表会导致各工位不一致）。

### 4.3 参数校验规则

| # | 规则 | 处理 |
|---|---|---|
| 1 | 费率范围 10~500 元/h、日产量 1~100000 件/日 | 超范围阻止保存并提示 |
| 2 | 日产量与TT一致性：daily_output > (3600×日有效工时h ÷ TT秒)×0.95 | 警示"日产量接近/超过TT理论产能，请核对"（日有效工时按8h计），允许保存但报告行脚注标注 |
| 3 | 任一参数未配置 | **阻止计算**：收益行显示"参数未配置，无法估算（IE主管维护）"，不猜默认值 |
| 4 | 落地率字段 | 界面只读展示0.70，写死在计算代码中 |

## 5. 一页对比报告版式与导出

### 5.1 区块清单（单页，自上而下）

| # | 区块 | 内容与数据源 |
|---|---|---|
| 1 | 报告头 | 产线/工位名、版本对 v(n)→v(n+1)、复测日期（v(n+1).updated_at）、生成时间 |
| 2 | 前后山积图并排 | 单工位=前后要素ST堆积条（VA/NNVA/NVA三色）；多工位项目=双山积图+TT线；口径=生效非异常要素 |
| 3 | 前后VA占比 | 两版 ΣVA_ST÷ΣST 环形图或数字对比 |
| 4 | 要素明细对比表 | §2.2 三档着色明细；配对率<60%时此区块替换为降级说明 |
| 5 | 6类浪费消除统计 | 前后两版按6类浪费（持住/重复取放/搬运/等待/寻找选择/检验冗余）ΣST 差额表，与劳永逸分析页口径一致 |
| 6 | 收益估算行 | 透明展示各因子：节省秒数×日产量×365×费率×70% = 金额，参数脚注注明"IE主管配置值" |
| 7 | 版本信息与IE署名行 | v(n)封存时间+封存时updated_by、v(n+1)提交人/时间、报告生成人（当前登录IE）；异常要素单列（数量+原因） |

### 5.2 导出实现（前端渲染，零重依赖）

- **PDF（定稿）**：`@media print` 打印样式（A4横版）+ `window.print()` 另存PDF，零依赖；
- **PPT（定稿建议）**：导出PNG图片（html2canvas，唯一前端依赖~40KB），IE自行插入周报PPT——"一页报告"以图片入PPT完全够用；若IE反馈强烈，P2再评估 PptxGenJS 生成真pptx（列为可选增强，不进W6）；
- 不做后端渲染服务、不引入 headless 浏览器。

## 6. 边界情况与降级处理

| # | 场景 | 处理规则 |
|---|---|---|
| 1 | 复测循环数<15被拦截 | 3条校验命中即拦截提交：v(n)保持生效可编辑、v(n+1)留草稿、对比页不可用；提示"补录循环或作废复测" |
| 2 | 改善后结构大变（配对率低） | 按 §2.3 阈值降级：<60% 只做工位级对比，收益取ΔCT；60%~80% 双口径并示、横幅提示 |
| 3 | 日产量取实际还是计划 | **定稿：取最近30天实际平均日产量**（MES取数、IE主管手填配置），不用TT理论值——收益是钱口径，实际产出决定真实兑现，计划值偏高会虚增 |
| 4 | 费率未配置 | 阻止计算+明确提示，不猜默认值（§4.3-3） |
| 5 | 同一工位多次复测 | **定稿：只比最近两版**（当前生效版 vs 其前一版，即 v(n-1) vs v(n)）；历史版本可查看（只读明细）不可再对比——链式累计会放大中间波动且口径漂移；需跨版（如 v1 vs v3）时导Excel人工算 |
| 6 | 复测中途放弃 | "作废复测"删除v(n+1)草稿，v(n)恢复为当前生效版（封存=只读≠失效） |
| 7 | ECN/设计变更混入 | 后版新增要素默认计负贡献；IE勾选"属设计变更"后剔除，脚注记"剔除设计变更要素K条"（对齐全局口径：ECN增删不是改善） |
| 8 | 后版异常率>20% | 提示数据质量存疑，报告头黄色标注，不阻止出报告 |
| 9 | 负节省 | §3.1：红色显示不截断，多工位报净值但明细必列 |

## 7. 与原效益核算体系的降级映射

### 7.1 原四步换算链 → 一行公式

| 原方案（Phase 2） | MVP去向 |
|---|---|
| ① 单站循环节省 ΔST站 | **保留**：即"节省秒数"（工位级ΔCT / 要素级配对差） |
| ② 全线单件节省（重平衡后口径） | 吸收进"Σ各工位ΔCT"；不做重平衡再编成（P2） |
| ③ 人力节省ΔHC（取整+最少编成约束） | 被"日产量×综合费率×365"吸收：按秒×产量线性折算，**不取整**（偏乐观，由70%落地率部分对冲）；减员路径（自然流失→并线）不进系统 |
| ④ Hard/Soft/NWC分类判定+签认+台账 | **全部砍掉**：Hard/Soft/NWC差异吸收进"综合费率"的全成本口径（DL全成本+制造费用分摊，元/工时）；不判定、不签认、不入账 |
| 口径#7 HR官方费率表 | 降级为IE主管手填单值（无取数依据留存） |
| 口径#8 当量产量 | 试点线单机型默认自然件数；多机型时列待确认项 |
| 口径#4 30天复测±5% | 降级为"实施完成后择期复测一次"，不强制30天与偏差复测（学习曲线提示见下） |
| 口径#10 70%落地率 | **保留**（写死） |
| 三层KPI/月报/仪表盘 | 砍掉，Excel导出顶住 |

### 7.2 升回路径（触发闸门：财务/管理层明确要求报数口径）

闸门触发后按序加回，仍不做Hard/Soft体系（蓝图7.2）：
1. 第一步（最小增量）：t_improvement 加 `verified_save_s` 字段 + 效益台账Excel导出（此时才允许动表结构）；
2. 第二步：费率表官方化（HR取数依据+更新日期+半年刷新）、日产量当量化、年化改财年口径；
3. 第三步：HC取整+最少编成约束、四件套证据链（快照/复测/MDL/签认）、Hard/Soft初判规则——即恢复Phase 2方案①~④换算链。

## 9. 待确认项

1. 复测触发是否加"距建议实施≥7天"稳定期提示（建议：仅提示不拦截，学习曲线剔除不做）；
