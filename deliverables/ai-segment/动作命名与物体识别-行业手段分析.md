# 动作类型/要素名称自动识别与录入：行业实现手段分析

> 问题：①行业如何自动识别动作类型/要素名称并录入？②「拿取扫描枪于放置支架」这类动作在最佳实践中如何实现？
> ③是 AI 分解后人工标注，还是先导入 SOP 再自动标注？④物体识别有哪些实现手段？
> 关联：`AI视频分解落地方案推荐.txt`（推荐方案）与本系统 v3.43 P1 已落地能力。

---

## 一、核心结论（先答问题）

1. **行业主流 = 「AI 提议 + 人工确认终裁」，两种起点并存但作用不同**：
   - **冷启动（无 SOP）**：AI 通用分解 → 人工逐条标注/修正。人工数据沉淀为该工位的训练集与模板。
   - **有 SOP（推荐路径）**：先把标准作业流程/标准工时库导入为「词表 + 期望序列」，AI 分解被约束在这个**封闭词表**内做分类与对齐 —— 从「开放命名」变成「封闭分类」，可靠性高一个量级。
   - 纯自动标注（无人确认）**不是**行业最佳实践：Retrocausal、Coats GSD、Invisible AI 等头部产品全部保留工程师确认环节，原因有二：现场责任归属（工时数据进薪酬/排产）与模型置信度不足。
2. **「拿取扫描枪于放置支架」不是端到端命名出来的，而是「动词 + 对象 + 位置」拼装出来的**：
   - **动词**（拿取/放置/使用）来自运动学模式（位移轨迹、能量形态、握取-释放节律）——本系统 v3.38b 的 6 类规则分类已在做这一层；
   - **对象**（扫描枪）来自**物体识别/物体轨迹**——推荐方案 §5 的 YOLO 检测层，本系统目前缺的就是这一块；
   - **位置**（放置支架）来自**区域标定**（ROI 内再划功能子区）或物体重叠关系；
   - 最终名称 = 描述模板实例化。**本系统的标准库描述骨架（`拿取[对象于：][位置：][距离：]`）与行业做法完全同构**，差的只是「对象/位置」两个字段的自动填充。
3. **物体识别的行业手段（按成本升序）**：

| 手段 | 原理 | 成本 | 适用 | 代表 |
|---|---|---|---|---|
| ① 固定区域标定 | 把「支架/料箱/扫码区」框成 ROI 子区，物体质心进入即判 | 极低（本系统 ROI 配置化已具备扩展位） | 工位布局固定 | 几乎所有工业视觉方案的基础层 |
| ② 标记物（marker） | 现场贴二维码/ArUo/色块，检测标记=检测物体 | 低（贴标签+通用检测） | 物料位置固定、怕训练成本 | 仓储 AGV、电子装配 |
| ③ 手-物交互状态机（HOI） | 「手接近→接触→物体跟随手→离开原位」=拿取；反向=放置 | 中（无检测时用运动质心近似，有检测时精确） | 判断「拿/放」语义 | Drishti、uituning 类 |
| ④ YOLO 逐工位微调 | 标注 200~500 张/工位，训练 8~15 类 | 中高（标注+训练+维护） | 批量推广、物形多变 | 推荐方案 §5 |
| ⑤ VLM 关键帧问答 | 抽证据帧问多模态模型「手里拿的是什么」 | 中（按帧计费；零训练） | 冷启动命名、低频校验 | GPT-4V/Qwen-VL 类 |
| ⑥ 背景差/模板匹配 | 固定机位下物体出现/消失 | 低 | 物体进出固定卡位 | 传统机器视觉 |

   **对本系统的建议顺序：③（HOI 状态机，纯算法零训练）→ ①（ROI 子区，复用 v3.43 配置化）→ ⑤（VLM 只看证据帧，与 P1-1 天然协同）→ ④（量大后再上 YOLO）**。②在防错/防呆场景价值高但改变现场作业习惯，需与产线协商。

## 二、行业产品的实际录入流程（三种模式）

### 模式 A：AI 分解 + 人工标注（冷启动）

```
拍视频 → AI 通用切分（能量/姿态）→ 人工逐段定：动词 + 对象 + 位置 → 确认入标准工时表
```
- 人工标注的每一条都成为该工位的「模板样本」；下个循环 AI 按模板自动预填，人只改差异。
- **本系统现状即此模式**：候选 → 人工改类型/补描述（标准库骨架）→ 写入。已有「人机协作飞轮」的骨架。

### 模式 B：SOP 先导 + 自动标注（有标准库）

```
导入 SOP（步骤序列 + 每步期望动作词 + 预期对象/区域）
→ AI 分解出候选段
→ 序列对齐（漏步/重复/顺序错误检测）
→ 段 × SOP 步骤 匹配 → 自动填名称（动词来自 SOP、对象来自物体层/区域）
→ 人工只处理「对不上」的少数段
```
- 这是效率最高、最可信的模式：AI 命名空间被 SOP 封闭，幻觉无处容身。
- **本系统具备两个前提**：动作标准库（motion_standard 词表+描述模板）与程序分析工具（SOP 数据源）。P2-2 的「SOP 规则对齐」就是把这条链补上。

### 模式 C：混合闭环（行业终态）

```
模式 B 为主链 + 模式 A 兜底（SOP 没覆盖的动作）
+ 人工修正回流：改过的类型/对象进入工位先验 → 逐工位阈值与模板自适应（推荐方案 §10 反馈闭环）
```

### 「拿取扫描枪于放置支架」的全链路（模式 B 视角）

```
视频段 t=12.0~14.8s
→ 感知：运动质心从「支架区」→「主机区」，中途在「扫码枪卡位」停留 0.4s（HOI：接触+跟随=拿取）
→ 动词：拿取（位移+握取节律；或 SOP 步骤 S1 的期望动作就是拿取）
→ 对象：扫码枪（YOLO 检测 / 卡位子区被离开 / VLM 看证据帧「手里是长条形带红光设备」）
→ 位置：主机区（质心终点所在子区）
→ 名称：拿取[扫描枪][至主机区] ← 模板实例化，人工确认后入要素
```
   每一步都有可解释依据（运动轨迹/区域/检测框），这正是推荐方案 §14「大模型只生成建议、必须绑定规则和证据」的落地形态。

## 三、与推荐方案的差距对照（更新版）

| 能力 | 推荐方案 | 本系统 v3.43 后 | 差距 |
|---|---|---|---|
| 动词识别 | LSTM/状态机 | 运动学 6 类规则（状态机等价） | 已补齐到「状态机」档 |
| 对象识别 | YOLO 8~15 类 | 无（ROI 有扩展位） | **P2-1（HOI+Pose）→ P3（YOLO）** |
| 位置识别 | ROI 重叠 + 质心落区 | ROI 单层（无子区） | ROI 子区化，成本低 |
| SOP 对齐 | 步骤顺序约束 | 无 | **P2-2 规则对齐** |
| 名称生成 | 模板 + LLM 辅助 | 标准库骨架（对象/位置人工填） | 结构一致，待对象层填充 |
| 证据链 | evidence_frames | **v3.43 已落地（三帧证据）** | ✓ |
| 逐工位 ROI | 每工位单独配置 | **v3.43 已落地（框选+落库）** | ✓ |
| 验收基线 | ≥70%/±2s/≥60% | **v3.43 已具备工具（真值集+eval 脚本）** | 待标注真值 |
| 浪费规则直判 | IE 规则库 | **v3.43 等待/双手不平衡已落地** | ✓（其余浪费依赖对象层） |

**结论**：P1 落地后，本系统在「证据链/ROI 配置/评测基线/等待与双手浪费」上已与推荐方案对齐；
剩余差距集中在**对象语义层**（物体识别→对象/位置自动填充→SOP 对齐），即 P2-1/P2-2 与 P3 的范围。
按本文 §一.3 的成本阶梯推进，可在不上标注团队的前提下先拿到 HOI+ROI 子区+VLM 证据帧问答的三级能力。

## 四、落地路线（衔接对比报告 P2/P3）

```
P2-1（对象层 MVP，纯算法）：ROI 子区化（支架/料箱/扫码区各存一个矩形）
  + HOI 状态机（质心进入子区停留→跟随→离开 = 拿取该区物体）
  → 描述骨架自动填「对象=子区名」、位置=终点子区名
P2-2（SOP 对齐）：程序分析/SOP 步骤导入 → 候选序列对齐 → 封闭词表自动命名
P2-3（VLM 校验，可选）：低置信候选的证据帧发给 VLM 问「这是什么/在做什么」
  —— 只处理低置信片段，成本可控（推荐方案 §10 的正确用法）
P3（YOLO 微调）：同型工位 ≥5 个且上述仍不达标时启动
```
