# Web 应用性能与安全测试策略

> 适用对象：IE 改善效率平台（React 19 SPA + NestJS API + SQL Server CN_AME，IIS ARR 反代）
> 版本：v1.0 · 2026-10-24 · 被测基线：本地回环实例实测（见第 6 节）
> 定位：**能卡住发版的策略**，不是测试清单的罗列。每一条都写明"怎么测、期望什么、不达标意味着什么代价"。

---

## 1. 一页结论

**现状判断**：功能测试底子扎实（smoke 139 / integration 31 / dashboard 30 / auth 48 / settings 20 / diff 15，UI 自动化 40 条），但**性能与安全基本处于"靠自觉"状态**——没有 SLO、没有门禁、没有常态化探针。本次实测直接用脚本抓到 **3 个高危项 + 1 个中危项**，全部是配置级缺失，修复成本以小时计。

**三件事，按性价比排序**：

| 优先级 | 动作 | 工作量 | 拦住的损失 |
|---|---|---|---|
| **P0** | 限流键改用可信 IP（信任链收敛）+ 登录接口加限流 | 0.5 人日 | 撞库/暴破打穿账号体系；XFF 伪造使现有 3 条限流形同虚设 |
| **P0** | 上安全响应头（nosniff/XFO/Referrer/CSP）+ 去掉 `X-Powered-By` | 0.5 人日 | 点击劫持、MIME 嗅探型 XSS、框架指纹 |
| **P1** | `/api/metrics` 收权限；API 响应开 gzip | 0.5 人日 | 基础设施拓扑外泄；10KB 聚合体每次裸传 |

**不建议现在做的**：全量 OWASP 扫描、渗透测试外包、k6 千级并发压测。理由见第 8 节"边界"——你们的真实风险不在 DDoS，在**内网权限越权 + 账号冒充**。

## 2. 被测系统的信任边界（决定测试往哪打）

```
[用户浏览器]
   │  React SPA（access token 存内存 15min / refresh token 存 localStorage 7d 轮换）
   ▼  HTTPS（由 IIS ARR 终结）
[IIS ARR 反向代理]  ← X-Forwarded-For 在此注入
   │  HTTP 127.0.0.1:3001（仅回环，不可外联）
   ▼
[NestJS API]  全局守卫链：JwtAuthGuard → TenantGuard → PermissionsGuard（24 权限点）
   │            TenantInterceptor 用 AsyncLocalStorage 在仓储层自动附加 tenant_id
   ▼
[SQL Server CN_AME]  业务库 + CMC 只读跨库查询
```

**四条边界，四条测试主线**：

| 边界 | 攻击面 | 必测内容 |
|---|---|---|
| 浏览器 ↔ 网关 | 传输机密性、XSS 窃取 localStorage、CSP | HSTS/证书、XSS 存储型、CSP、点击劫持 |
| 网关 ↔ API | XFF 信任链、明文回环、直连绕过 | 限流键可信性、ARR 是否覆写 XFF、127.0.0.1 是否可被同机进程访问 |
| API 内部 | 租户隔离、权限点、字段级泄露 | 四类越权（横向/纵向/租户/字段） |
| API ↔ DB | 注入、跨库读权限、连接池 | 参数化校验、CMC 只读账号权限边界 |

**关键事实（已核验，非假设）**：
- 应用层无 helmet、无 compression、无全局 Throttler；限流只散落在 `auth.service.ts` 的 4 个内存桶（register/forgot/reset，登录**没有**）。
- `clientIp()` 取 `x-forwarded-for` 的**第一个值**——客户端可伪造，实测可绕过限流（第 6.2 节有完整证据链）。
- refresh token 存 localStorage：一旦有任何 XSS，等于长期会话被拿走（access 15min 可等过期，refresh 7d 不行）。
- 原生 SQL 均为 `q()` 转义 + 数字正则校验后拼接，未见 `${}` 直插用户字符串——**当前安全，但属于"纪律型防御"**，需要回归用例锁死。

## 3. 风险模型：把测试预算花在会赔钱的地方

| 风险 | 后果 | 可能性 | 处置 |
|---|---|---|---|
| 越权读取他厂工位数据 | 客户间数据泄露 = 合同级事故 | 中（多租户已上线，权限矩阵仅 5 角色覆盖） | **重点测**：权限矩阵表驱动 |
| 账号暴破/撞库 | 弱口令账号被顶替（种子口令 `123456` 在现网很常见） | 高（无限流） | **重点测**：认证专项 |
| 分析结果被静默算错 | 客户按错数据做投资决策 | 中（规则版本/符号类不发布即算 0） | 已有口径测试，补"规则发布后回归" |
| 驾驶舱月会卡顿 | 演示现场卡 → 产品信任崩塌 | 中（聚合接口 10KB / 250ms，无缓存） | 性能测：峰值场景 |
| 视频工作台拖时间线掉帧 | 现场 IE 放弃使用 | 中（127KB 单文件组件 + NLE 帧精修） | 前端性能测 |
| 数据库被拖库 | 全量 BOL/工时数据 | 低（内网） | 依赖扫描 + 最小权限账号 |

**不测的**：DDoS 防护、CDN 回源、WAF 规则调优——这些是基础设施职责，列入上线前联合验收即可。

## 4. 性能测试策略

### 4.1 指标体系与 SLO

三层指标，各管各的事：

| 层 | 指标 | 采集方式 | SLO（内网，并发假设 30 人） |
|---|---|---|---|
| **前端** | LCP / INP / CLS | Lighthouse + 真实 Chrome trace | LCP < 2.5s，INP < 200ms，CLS < 0.1 |
| **前端（业务）** | 时间线拖拽帧率、长任务数 | Chrome Performance 录制 | 拖拽 ≥ 50fps，单长任务 < 100ms |
| **API** | p50/p95/p99、错误率 | k6 / 基线探针 | p95 < 800ms，p99 < 2s，5xx < 1% |
| **API（热路径）** | 驾驶舱聚合、工位列表、分析引擎 | k6 分端点阈值 | 聚合 p95 < 1.2s，列表 p95 < 400ms |
| **资源** | SQL Server CPU/连接数/等待类型、Node 堆 | Prometheus（已有 prom-client） | 稳态 CPU < 60%，连接池占用 < 70% |

> **并发假设需你确认**：当前 SLO 按"全厂 30 人同时在线、峰值 10 人同时拉驾驶舱"设计。若实际是"区域月会 50 人同时看大屏"，p95 门槛要上调到 1.5s 并加缓存。

### 4.2 五类场景（缺哪类就漏哪类问题）

| 场景 | 目的 | 参数 | 频次 | 判定 |
|---|---|---|---|---|
| **基准（baseline）** | 建立可比基线，抓回归 | 1 VU 顺序 30 次 | 每次发版 | 与上次基线偏差 < 20% |
| **负载（load）** | 稳态容量 | 10 → 30 VU 阶梯，5 分钟 | 每次发版 | 全部 SLO 达标 |
| **突刺（spike）** | 月会/批量导入瞬时冲击 | 5 → 120 rps 十秒内 | 月度 | 无 5xx，p95 恢复 < 60s |
| **浸泡（soak）** | 内存泄漏、连接池耗尽 | 8 VU × 30 分钟 | 季度 | 堆增长 < 15%，无连接泄漏 |
| **容量（capacity）** | 找拐点，定扩容线 | 逐步加 VU 至 SLO 破裂 | 季度/大版本 | 记录拐点 VU 数 |

**已被验证有效的两条纪律**：
1. **只压读、不压写**。写接口压测只允许在影子库做——否则批量评定/工位保存会在共享测试库留下脏数据，后续所有测试基线失效（你们踩过：冒烟工位必须收尾清理）。
2. **每轮跑 3 次取中位数**。本次实测驾驶舱 p50 在不同轮次为 85 / 165 / 190ms（冷热缓存 + SQL 执行计划差异），单次数据不足以判断劣化。

### 4.3 热路径清单（测点，按优先级）

| # | 路径 | 为什么是热点 | 注意 |
|---|---|---|---|
| 1 | `GET /dashboard/summary` | 全表聚合 + 跨租户维度解析，10KB 响应 | 首屏必调，月会必用 |
| 2 | `GET /stations`（列表 + 要素） | 工位多时 N+1 风险 | 需造 200 工位数据集 |
| 3 | 分析引擎 `analyzeStation` | CPU 密集，纯 JS 计算 | 大数据集下单次 < 300ms |
| 4 | 视频工作台首屏 + 时间线拖拽 | 127KB 组件 + 视频 seek | 前端主战场，见 4.4 |
| 5 | 批量评定 / 导入 | 长事务，可能锁表 | 只在影子库压 |
| 6 | AI 分析任务 | 异步队列，可能堆积 | 测队列积压而非单请求延迟 |

### 4.4 前端性能专项（SPA 特有）

当前构建产物：**单 chunk 505KB → gzip 152KB**，CSS 68KB → 13KB。内网可接受，但有三处要盯：

1. **首屏无拆包**：工作台是重页面（视频 + 时间线 + 检查器），驾驶舱是轻页面。若首屏都要加载全量 JS，驾驶舱首屏被工作台拖累。建议按路由 `React.lazy` 拆包，然后以 **驾驶舱 LCP** 作为前端门禁指标。
2. **时间线拖拽的帧率**：这是你们的差异化交互（NLE 帧精修、`<video>.currentTime` seek）。Chrome Performance 录制脚本化拖拽 5 秒，看是否出现 > 100ms 长任务、是否掉到 30fps 以下。已知负 `playbackRate` 必抛错（改为"点按后退"是对的），性能测试要覆盖这条路径的渲染成本。
3. **视频片段播放的取消与重启**：快速连续 seek 时 `play()` 的 Promise 会 reject，若未捕获会掀翻 React 树——性能测试顺带覆盖稳定性。

## 5. 安全测试策略

### 5.1 对标与裁剪

以 **OWASP ASVS 4.0 Level 2** 为骨架裁剪：L1 全过、L2 取与本系统相关的（认证、会话、访问控制、输入校验、错误处理、日志）；**显式排除** L2 中与当前架构无关的项（如 SAML/OAuth 联邦、支付卡、文件上传病毒扫描——当前无上传接口）。

### 5.2 必测 12 类（每类给判定口径）

| # | 类别 | 怎么测 | 期望 | 不达标的代价 |
|---|---|---|---|---|
| 1 | **认证** | 正确/错误口令、不存在用户、禁用/待审/锁定账号各一次 | 统一 401 文案，无枚举差异 | 撞库、账号画像 |
| 2 | **会话** | refresh 轮换、旧 token 重放、改密后旧会话 | 重放触发全族吊销；改密后 refresh 全失效 | 令牌被盗后长期潜伏 |
| 3 | **限流** | 同 IP 连打 + 轮换 XFF 连打 | 出现 429 且**换 XFF 仍 429** | 暴破无限次（**已实证失败**） |
| 4 | **纵向越权** | viewer1 调 admin 专属接口（用户管理/规则发布/租户配置） | 403 | 只读用户改规则 → 全厂算错 |
| 5 | **横向越权** | ie1 读写 other1 的工位/要素（改 ID 直连） | 403/404，**绝不 200** | 同事间数据互改，责任无法追溯 |
| 6 | **租户越权** | other1(OTHER) 拉 DEFAULT 数据；`x-tenant-id` 伪造 | 403 且响应体不含他租户 ID | 客户间泄露（合同级） |
| 7 | **字段泄露** | 用户列表/审计导出是否含 password_hash、内部 ID | 无敏感字段 | 哈希外泄可离线爆破 |
| 8 | **注入** | `factory_id=1;DROP`、`line_id=1 OR 1=1`、`username=' OR '1'='1` | 400（类型校验拦下） | 拖库 |
| 9 | **XSS** | 工位名/描述/备注写入 `<img src=x onerror=...>` 后在各列表复查 | 原样显示不执行；有 CSP 兜底 | 配合 localStorage refresh token = 长期接管 |
| 10 | **错误信息** | 触发 5xx（临时断开 DB） | 只回 `request_id`，不回堆栈/SQL | 攻击者拿到表结构 |
| 11 | **CORS/CSRF** | 任意 Origin 请求；无 Origin 的表单跨站提交 | 不回显 Origin；Bearer 头认证本身免疫 CSRF（需确认无 Cookie 认证路径） | 跨站代操作 |
| 12 | **审计完整性** | 登录/改密/规则发布/工位删除是否留痕、能否删改 | 只增不改，含 user/ip/时间 | 出事故查不清 |

### 5.3 权限矩阵：表驱动，别手写用例

原文为 24 个权限点 × 5 个角色 = 120 格；**2026-10-30 当前口径**：字典 26 项，`analysis:run` 未绑定控制器路由，实际执行为 25 个路由权限点 × 5 个隔离种子账号 = **125 格**。ie_admin 无独立种子账号，不能表述为五角色全覆盖。手写用例既累又会漏，**用一张矩阵 + 一个遍历脚本生成全部用例**：

```
routes[] × {role: expected_status}
  for each route: for each role: 登录该角色 → 请求 → 断言期望状态
```

矩阵维护方式：新增权限点/控制器时**必须同步矩阵代表路由**；脚本会对比控制器实际权限点与路由表，不一致即失败。当前只有本地预检命令，尚无 CI 载体。

### 5.4 两个专项论证（不做会误判）

- **refresh token 存 localStorage 的风险重估**：风险不在存储位置本身，在于**是否真的没有 XSS 出口**。因此第 9 类（XSS）不是可选项，而是这条设计的补偿控制。若后续引入富文本/HTML 描述，必须先把 XSS 用例跑绿再上线。
- **明文回环是否可接受**：`app.listen(port, '127.0.0.1')` 只在同机可访问，同机提权者本就能读内存，风险可接受。**但要测**：ARR 是否真的只反代到内网、`X-Forwarded-For` 是否被 ARR 覆写而非追加（若是追加，`clientIp` 取首值即被伪造——这正是实测暴露的问题）。

### 5.5 依赖与供应链

- `npm run test:deps` 对 api/web 分别执行 `npm audit --omit=dev --json`，**high/critical 阻断、moderate/low 记账**；当前仅有本地门禁，尚无 CI 载体。
- 关注 4 个高风险依赖：`sqlite3`（原生模块，且生产不用——可考虑移出 prod 依赖）、`mssql`、`passport-jwt`、`bcryptjs`。
- `x-powered-by` 已暴露 Express 指纹（实测存在），一行关掉。

### 5.6 安全测试红线

- **不对生产库做任何写/删探针**；越权测试用只读 GET 或不可解析 ID。
- **不把真实账号打到锁定**（本次探针用不存在用户名 + 登录失败不重试）。
- 注入/暴破类主动扫描**只在隔离环境**跑，且跑完清理审计表增量。

## 6. 实测基线（2026-10-24，本地回环，`BASE=http://127.0.0.1:3001/api`）

### 6.1 性能

| 测点 | 结果 | 判定 |
|---|---|---|
| `GET /health` 顺序 30 次 | p50 3.2ms / p95 6.0ms / max 10ms | 通过 |
| `GET /dashboard/summary` 20 次 | p50 85–190ms / p95 129–255ms / 10,474 B | 通过（待优化） |
| 20 并发 × 3 波（health） | 79.8 / 59.4 / 46.3ms，错误 0 | 通过 |
| 响应压缩 | **无 `content-encoding`** | 失败（低） |
| 前端产物 | JS 505KB→152KB gz，CSS 68KB→13KB gz，单 chunk | 可接受，建议拆包 |

> 驾驶舱 250ms、10KB 未压缩，在内网 30 人下没问题；但**若月会 50 人同时打开**，等于每轮 500KB 裸传 + 50 次全表聚合，是第一个会响的地方。加一层 30s 缓存 + gzip 即可解。

### 6.2 安全（脚本判定，证据可复现）

| ID | 项 | 严重度 | 实测证据 |
|---|---|---|---|
| SEC-01 | 安全响应头全缺 | **高** | 缺 nosniff / X-Frame-Options / Referrer-Policy / CSP / HSTS；且存在 `X-Powered-By` |
| SEC-03 | `/api/metrics` 公开 | 中 | 未带 token 返回 200，18,868 B 指标（含路由、状态码分布） |
| SEC-15 | 登录无限流 | **高** | 不存在用户连打 20 次，全部 401，**无一次 429** |
| SEC-16 | 限流键可被 XFF 伪造绕过 | **高** | 同 IP 打满 5 次后正常 429；改伪造 `x-forwarded-for` 后 **8/8 全放行** |
| SEC-13 | 跨租户隔离 | 未判定 | other1 请求驾驶舱返回 403（权限挡住，未触达数据层）——**需用具备 dashboard 权限的账号重跑** |
| SEC-04/05/06/07 | 无令牌 401、伪造 JWT 401、畸形 JSON 400、错误体不泄露 | 通过 | — |
| SEC-08 | CORS 不回显任意 Origin | 通过 | `ACAO` 为空（生产需确认 ORIGIN 环境变量已设，勿留 localhost 默认值） |
| SEC-09 | 弱口令被拒 | 通过 | `abc` → 400 |
| SEC-12 | `x-tenant-id` 伪造被拒 | 通过 | 403 |

**SEC-16 的根因与修法**（这是本次最有价值的发现）：

```ts
// 现状：无条件信任 XFF 首个值
const fwd = req.headers['x-forwarded-for'];
return raw?.split(',')[0]?.trim() || req.ip;   // ← 客户端可写
```

修法（三选一，推荐第 1 条）：
1. 只信任网关写入的那一段（ARR 场景下取**最后**一个值，或配置可信代理白名单后取最后一个非内网地址）；
2. 登录也纳入限流桶，并对"同账号失败"独立计数（账号维度 + IP 维度双桶）；
3. 多实例部署时把桶迁到 Redis（当前内存桶在 PM2 多进程下各自计数，等于限流值 × 进程数）。

## 7. 缺陷分级与出口准则

| 级别 | 定义 | 处置窗口 | 例 |
|---|---|---|---|
| **P0 阻断** | 可越权/可冒充/数据错 | 立即修，**阻断发版** | 租户越权 200、限流可绕过、VA 算错 |
| **P1 高** | 放大攻击面或明显性能不达标 | 当迭代修 | 无安全头、登录无限流、p95 超 2 倍 |
| **P2 中** | 有缓解措施或影响局部 | 排期修 | metrics 公开、无压缩、单包过大 |
| **P3 低** | 体验/卫生问题 | 顺手修 | X-Powered-By、依赖中危 |

**发版出口准则（三条全绿才发）**：
1. 安全 critical = 0，high ≤ 1 且有明确缓解；
2. k6 负载场景全部 threshold 通过，或劣化有书面说明；
3. 权限矩阵全绿（当前 125 格；被拒分支不得 unexpected 2xx，且必须准确 403）。

## 8. 边界与不做的事

- **不承诺零缺陷**：测试降低风险，不消除风险。给管理层的口径是"已知高危项清零 + 关键路径覆盖"，不是"没有 bug"。
- **不用自动化冒充渗透测试**：注入绕过、逻辑越权链、业务欺诈需要人工+专业工具（Burp/ZAP）。建议**上线前请一次外部渗透**，针对性打多租户与 RBAC。
- **不在生产做破坏性测试**；紧急热修复走"最小必要测试（认证 + 权限矩阵 + 基线探针）→ 事后补齐"。
- **不压写库**：写接口容量评估用影子库或直接按业务量估算。
- **不追求 100% 行覆盖率**：这个系统的风险集中在权限与口径，不在代码行。
