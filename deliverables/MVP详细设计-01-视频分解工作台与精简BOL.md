## 1. 视频引擎规格

| 项 | 规格 | 验证标准 |
|---|---|---|
| 支持格式 | mp4 / mov / avi / mkv / webm（浏览器原生解码为主，H.264编码优先） | 5种格式各1样本可正常播放 |
| 分辨率/帧率 | 1080p / 30fps 标准；含<1秒快要素的工位60fps | 播放器读出实际帧率 |
| 单文件大小 | ≤2GB，时长≤30min（拍摄规范：连续≥25循环对应时长） | 超限拒绝上传并提示 |
| 倍速档位 | 0.1× / 0.25× / 0.5× / 0.75× / 1× / 2× / 4× / 8×（快捷键↑↓换档） | 8档切换无花屏 |
| 逐帧步进 | 按视频实际帧率：30fps→33.3ms/帧，60fps→16.7ms/帧；快捷键←→单帧，Shift+←→ 10帧 | 播放头时间戳显示到ms |
| 局部放大 | 时间线区域鼠标框选→2×/4×放大（滚轮切换倍率），放大窗口独立播放；用于观察握取/预对等微动作 | 框选即出放大窗 |
| 多文件 | MVP不做多段合并（原蓝图P0项砍为延后），一条视频拍不下分两次拍、分两次分解 | — |

帧率约定：**所有时间戳以ms整数存储（start_ms）；1帧=可分辨的最小时间单位，拖拽/分割步长不得小于1帧。**

## 2. 时间线+要素编辑器交互规格

## 3. 循环识别算法

### 3.1 循环边界检测（手动标记为主+结构校验为辅）

| 步骤 | 规则 |
|---|---|
| ① 定锚点 | IE选定"周期性起止锚点"=每循环第一个动作的同一事件（如"右手触达取料点"），播放到锚点按 **M键** 打循环起点标记 |
| ② 连续标记 | 逐循环按M；相邻标记间隔=该循环CT，系统实时显示CT序列 |
| ③ 结构校验 | 系统对每循环内的要素序列做**签名比对**（type+hand序列）：签名不一致的循环标黄提示"第k循环要素结构与多数不一致，请核查是否漏录/多录"——提示不拦截 |
| ④ 边界即用 | 循环起点标记用于：BEST/WORST抽取、要素多循环观测对齐、CV计算 |

不做自动边界识别（P2再议）——试点线工位数少，M键标记成本每循环<1秒，自动识别的开发成本不划算。

### 3.2 CV计算与加测流程

- **CV = σ / μ**（σ=样本标准差，μ=均值；基于各循环总时间，单位s，保留3位小数）
- 交互流程：提交时系统计算。①cycle_count<15→拦截（第7节V3）；②15≤n且CV≤0.15→放行；③CV>0.15→弹窗"循环离散度CV=0.xx>0.15，需加测至25循环（当前n个）"：视频内还有未标记循环→继续标记；视频不够→提示补拍重录，**不允许提交**（快速预判场景用纸面/Excel，不入库，延续v1.1口径）；④已加测至25仍CV>0.15→**放行提交但标记"离散度异常"**（分析页可见）——25循环是MVP成本上限，CV持续偏高根因是方法不稳或变异单元混入，应靠改善解决而非无限加测。

## 4. BEST/WORST Lap一键抽取规则（定稿）

| Lap | 口径 | 理由 |
|---|---|---|
| **BEST** | 有效循环中，循环时间与**中位数偏差最小**的循环（\|CTᵢ−median\|最小；并列取先出现者） | ①中位数抗离群稳健；②"最快循环"常伴随偷步/漏装质量风险，不可作标杆；③代表性循环=可持续维持的稳定水平，直接用作标准作业示范与新人训练教材（OTRS10 Best Lap同用途）；④**BEST只做方法标杆，不做工时定值**——std_time仍按全体有效循环均值×评比（第5节），两者分工明确 |
| **WORST** | 循环时间**最长**的有效循环（不剔除；若其含已标异常要素，在结果中注明"含异常要素x条、异常时长y s"） | 最长循环就是要暴露的问题本身 |
| 差异展示 | WORST vs BEST 逐要素做差，**Δ≥0.3s 且 Δ≥20%** 的要素高亮为"差异要素"，点击跳转对应视频时刻——直接作为改善证据链入口 |

抽取结果=一段BEST视频剪辑区间+一段WORST视频剪辑区间+差异要素对照表，随分解结果写库后供分析页引用。

| # | 校验 | 触发条件（精确逻辑） | 报错文案 | 拦截行为 | 修正后流程 |
|---|---|---|---|---|---|
| V1 | 必填完整性 | ∃要素：type∉10类枚举 ∨ trim(desc)="" ∨ hand∉{L,R,B} ∨ va_class∉{VA,NNVA,NVA} ∨ (outlier_flag=1 ∧ trim(outlier_reason)="") ∨ rating∉[0.70,1.25] ∨ allowance∉[0.05,0.30] ∨ (va_class≠类型默认值 ∧ desc不含"[VA改判") | "要素#{seq}[{desc}]缺少必填项：{字段清单}；改判VA须在描述末尾追加'[VA改判\|原\|新\|理由\|人\|日期]'标记" | 提交按钮无效；时间线对应要素块红框+跳转首个错误 | 逐项修正后重新点提交，校验全量重跑（不增量放行） |

## 8. bol_version封存状态机

| 项 | 定稿规则 |
|---|---|
| 版本号 | 工位内自增整数，从v1开始；element_id含版本号，封存版本的主键永不复用 |
| 触发封存 | 点"**开始复测**"瞬间：当前生效版v(n)整体转只读；新建v(n+1)空白分解，与v(n)并排可参照 |
| 只读含义 | v(n)的**全部16字段锁定**，无任何编辑入口（含outlier标记与desc——"留底"要的是当时原貌，加备注=改历史）；仅允许查看、导出Excel、视频回放 |
| 版本判定 | 生效版本=t_station.version指向的bol_version；工作台只允许编辑"该工位最新且未封存"的版本 |
| 回退场景 | ①复测作废：删除v(n+1)草稿（未提交过库的本地缓存直接丢弃；已提交则整版本DELETE，同事务恢复t_station.version=n）→v(n)仍是生效版；②误封存：不允许"解封"v(n)（防篡改留底），正确做法是继续在v(n+1)上做 |
| 封存记录 | t_station.updated_by/updated_at记录操作人与时间，即"谁改、何时、改了什么"的最小留痕（无审批流） |

### 9.2 校验与失败处理

- 导入走**与工作台完全相同的V1/V2校验**+类型枚举+数值范围校验（一致性是数据质量的根）；
- **整批事务**：任一行失败→全部不导入，返回带"错误清单"sheet的Excel（行号+列名+原因）。逐行放行会污染刚建好的库，MVP阶段宁可重导；
- 成功后自动重算对应工位CT并提示"工位{n}个导入完成，CT已更新"。

## 12. 边界情况处理

| 场景 | 处理规则 |
|---|---|
| 同一工位多次分解（未点开始复测） | 同一bol_version内覆盖：提交即DELETE+INSERT（第10节），不留中间稿；版本只升不复用 |
| 视频重新上传 | video_id替换为新文件；已录要素**保留**；若新视频总时长<任一要素end_ms→V2前置校验报错"要素超出视频范围"，需先裁剪要素或还原旧视频 |
| 要素删除后seq重排 | 同工位按start_ms全局升序（L/R混编）重编seq=1..n，提交时统一执行；中间空号自动消除 |
| 单手工位 | 未使用的手别整列置灰显示"未使用"，hand枚举不出现B |
| dur_s小于1帧 | 禁止（校验提示"微动作请用60fps重拍"）；最小合法dur_s=1帧（0.03s@30fps按0.04s进位2位） |
| 循环数不足且现场无法补拍 | 拦截提交；预判走纸面/Excel，不入库（口径延续v1.1） |
| 提交后发现录错 | 未封存版本：重新进工作台编辑重提交（覆盖）；已封存：只能在新版本修正 |
| 复测时只想改个别要素 | 仍全量重新分解写v(n+1)——版本对比要求两版各自完整；旧版可并排参照，实际增量录入成本低 |
| Excel导入的工位无TT | TT默认0显示"—"，山积图TT线隐藏并提示补录 |

## 13. 待确认项（不自行扩围，报team-lead裁决）
