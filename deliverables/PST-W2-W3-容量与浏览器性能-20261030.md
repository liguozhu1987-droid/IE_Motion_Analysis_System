# W2/W3：200 工位 + k6、Lighthouse、真实桌面拖拽帧率（2026-10-30）

## 1. 执行结论

**本地隔离组合门禁全部通过**：k6 / Lighthouse / 有界面 Chrome 时间线三个阶段退出码均为 0。

- 固定数据：**1 产线 / 200 工位 / 4000 要素**，只写临时 `gate-performance.db`。
- k6：5 分钟 load（峰值 50 VU）+ 1 分钟 50 VU 同键缓存场景；**11,528 请求、8,650 次 check、失败 0**，全部 threshold 通过。
- Lighthouse 13.6.0 desktop：确认已登录并加载 200 工位综合看板；**LCP 1.082s、CLS 0**，达到 `<2.5s / <0.1`。
- 真实桌面 Chrome：固定 8 秒 1280×720 MP4、20 要素、连续真实鼠标拖拽约 5 秒；**DrawFrame 59.90fps、rAF 60.06fps、最长 RunTask 22.0ms**，达到双帧率 `>=50fps`、单任务 `<100ms`。

总判定：`PST-performance-gate.json` 的 `passed=true`。

## 5. 真实桌面时间线拖拽

- 目标：`PF-ST001`，20 要素；视频 `aiseg-8s.mp4`，SHA-256 `57cfd1e44d56851b4b908cabf9606f7eeb2b0bdfe9ceb00eec9d5dce8cb9a4bb`。
- 操作：CDP 真实鼠标按下右边界手柄，302 次移动后松开；块宽 `106px→136px`，证明不是空拖。
- **trace DrawFrame：311 帧 / 59.90fps**；rAF：316 帧 / 60.06fps。
- rAF 帧间隔：p50=16.6ms、p95=16.8ms、max=22ms；>20ms 仅 1 次。
- Long Tasks observer：0；trace RunTask max=22.002ms，>=100ms 为 0。
- JavaScript pageerror=0。

首版测试曾出现 rAF 60fps 而 DrawFrame 约 36fps，根因是测试驱动每次鼠标事件额外等待 16ms，导致输入只有约 30 次/秒。已改为真实连续事件，并把实际 DrawFrame 同时纳入门槛；不以 rAF 空转冒充拖拽帧率。
