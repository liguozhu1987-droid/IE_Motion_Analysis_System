双来源线 · 要素快照 · VA → 浪费 → 5W1H → ECRS/动作经济 → Case → 审核 → 实施 → 实际节省 · 2026-11-23

变化 1 · 来源线成为一等公民

  • 旧 To-Be：单一“输入层”，快照只隐含 task/version。
  • 新：手工线与 AI 线并行进入 SnapshotService，source 显式；跨线比较直接阻断；mixed 仅只读。
  • 影响：compare / diff / analysis / AI 建议 / 浪费识别都按来源线取数；措施能回答“针对哪条线的哪个要素”。
  • 状态：S0 已完成。

变化 2 · 方法链补进主干

  • 旧 To-Be：计算内核 → 机会生产，缺 5W1H 与动作经济。
  • 新：Analysis → 5W1H → 措施（ECRS + 动作经济 ME1–ME10 + est_save_s）→ ImprovementCase。
  • 影响：每条措施都有问题依据与原则编码；三条建议产线收敛为同一 Case 契约。
  • 状态：S1 待落地（Case 表需 DDL）。

变化 3 · 闭环与反馈拆成两条

  • 旧 To-Be：决策执行 → 验证/反馈，一条笼统回边。
  • 采纳支路：Writer → 闭环清单 → 实施回填 actual_save_s → 效果验证（预估 vs 实际）。
  • 拒绝支路：R1–R8 原因码 → 按 waste_type × ECRS 汇总 → 提示词负样本/阈值校准（带衰减与上限）。
  • 状态：拒绝原因码 S0 已落；回填与汇总 S1。

与旧 To-Be 的骨架对照

  • 旧：输入 → 事实 → 计算 → 机会生产 → 决策执行 → 验证/反馈
  • 新：双来源 → 快照 → 计算 → 5W1H → 措施 → Case → 审核 →（采纳）Writer → 清单 → 回填 → 验证 /（拒绝）汇总 → Skills
  • 不变：唯一事实源、唯一计算内核、唯一写入口、单向主链、下游不回写事实。
  • 新增：方法链（5W1H/动作经济）、Case 状态机、实际节省、结构化拒绝反馈。
