3.1 环节一 · IE 动作分析：从「怎么记」到「怎么存」

共性架构

  • 元素树模型：工作循环 → 操作 → 动作元素，三级结构是全部 5 款的共同数据骨架。
  • 方法描述与时间值分离：方法 = 编码序列（MTM 码 / MOST 序列 / MODAPTS 码 / 视频元素），时间 = 查表或公式计算的产物。这是最关键的一条架构经验——TiCon 与 Proplanner 因此能同时支持 MTM-1 / MTM-2 / UAS / MEK / MOST / MODAPTS 并允许企业「并行过渡」。
  • 宽放与标准时间计算：正常时间 × (1 + 宽放) = 标准时间，宽放（个人/疲劳/延迟）独立参数化。

对本系统最有价值的一条：TiCon Base 的「可复用元素系统」与 MOST 的「分层标准数据模型」都指向同一件事——不要让 IE 每次都从零拆动作。本系统目前每个工位版本独立存储要素，缺少跨工位/跨版本可复用的「标准要素块」，这是 ROI 最高的补齐项。

3.2 环节二 · 浪费识别：双维度分类法

共性架构

浪费识别在数据上是一个「元素打标签 → 聚合统计」的过程：先在每个动作元素上挂属性（是否增值、属于哪类损失），再按工位/产线/工厂维度 roll-up。真正决定能力上限的是标签体系的设计。

借鉴点：AviX 的「三态 + 五类」

  • 三态（活动性质）：作业性（Operational）/ 非作业性（Non-Operational）/ 准备（Preparation）——先在大类上把「生产活动时间」和「非生产时间」切开，避免把准备时间混进节拍。
  • 五类（损失类型）：增值 / 浪费 / 等待空闲 / 返工 / 非生产性——颜色编码，现场一眼看懂。
  • 关键价值：颜色分类在拖放平衡时实时刷新，让「改善动作」和「看效果」在同一界面完成，不用来回切页。

3.3 环节三 · 改善措施制定：ECRS + 承诺值

共性架构

措施制定 = ECRS 四象限（Eliminate 取消 / Combine 合并 / Rearrange 重排 / Simplify 简化）+ 方法再设计 + 重算标准时间，差额即预期收益。5 款软件的差异在于「比选」和「量化」的成熟度。

产品方案比选机制收益量化值得抄的点
TiCon 4Takt 模块可「冻结现状」并生成未来态方案，做并列比较；最大化线平衡按变体自动判定工序是否需要Cost 模块直出成本/报价「冻结现状 → 未来态 → 并列比」三步式；对应本项目已有的 /stations/:id/retest + /compare，可复用为「方案对比视图」
MOST纸面阶段即可建立多方案并比较，速度优势让「多比几版」变得可行为自动化投资提供被替代工时基线降低比选成本本身就能提升方案质量
MODAPTS码表级动作替换（如 M4G1→M2G1）MOD 数差额 × 0.129 s最轻量的量化，适合现场快速迭代
AviXResource Balance 拖放试算，实时看各工位 VA/NVA 变化对每个改善提案直接模拟节约时间，支撑投资决策即时模拟：拖拽即出数，无需另建模型
Motion-Mining情景推演（布局/路径/ staffing）量化潜力（公开案例：拣货+包装年省约 23 万欧）用绝对金额而非百分比汇报，易获管理层批准

4.4 具体改进建议（按可执行度排序）

  1. 把「要素」从「工位私有数据」升级为「可复用资产」。在工作台每条要素上加「存为标准块」，在创建要素时提供「从标准块插入」。标准块带适用条件（对象/距离/重量/精度），插入时按条件自动匹配时间值。这是 TiCon Base 与 MOST 主标准库的共同做法，能把重复分解工作量压掉一大块。
  2. 给每条要素补两个标签：activity_nature + loss_type。只加字段、不改现有 VA/RNVA/NVA 逻辑，成本低。加完即可在 AnalysisPage 出「损失帕累托图」，直接回答「浪费主要在哪」，而目前只能回答「动作不经济在哪」。
  3. 把「建议」做成有承诺值的契约，而不是一段文字。adopt 时强制填 ECRS 类型 + 承诺节约秒数 + 责任人 + 期限 + 验证方法。缺项不给采纳（或标记为「草稿级建议」）。
  4. 打通「承诺 → 复测 → 校核」。复测生成新版本后，自动把该工位关联的、状态为「已实施待验证」的建议逐条比对：承诺 vs 实测。偏差 > 5%（可配置）的建议不允许流转到「已完成」，必须先填偏差原因。这条规则在 REFA/MTM 体系里是标准做法，是让标准时间「活」起来的关键。
  5. 让 AI 与人工的差异显式化。输出 coverage 与 agreement 两个指标。IE 打开 AI 结果时，第一眼看到的是「这 136 条里有 41 条置信度低，优先复核这 41 条」，而不是面对 136 条无从下手。这正是 Motion-Mining 用自动识别抢时间、又不放弃人工复核的思路。
  6. SOP 导出件带上时间码。v3.44 已有 sop_steps 与 HOI，差的是「一键导出」。产出物含：动作序列、每步起始时间码、关键动作视频帧、注意事项。现场扫码即可看，等于把 AviX Shopfloor Viewer 的核心价值搬进本系统。
  7. 把人因负荷纳入改善优先级排序。有了 ROI 与关节点，做简易 EAWS/REBA 子集评分并不难。做法：工位级红/黄/绿，仅作为排序权重与提示，不替代专业人因评估，界面显式标注「待现场验证」。
  8. 采集端的合规前置。视频涉及员工影像，建议提供入库脱敏选项与留存期配置，操作全审计。Motion-Mining 把「匿名化 + GDPR 合规」做成核心卖点，说明这在落地时是真痛点，不是纸面功夫。
