## 2. VA/NNVA/NVA归类规则表

判定总纲：VA=直接改变产品形态/性能/性质（客户付费）；NNVA=不增值但当前工艺必需（只能压缩）；NVA=纯浪费（目标删除）。改善优先序：删NVA→减NNVA→简VA，顺序不可颠倒（该优先序供建议引擎排序使用）。

### 2.1 逐类型默认判定（10类）

| 要素类型 | 默认归类 | 置信度 | 例外条件（命中即转低置信度，进待复核） | 判定理由模板 |
|---|---|---|---|---|
| 装配 | VA | 高 | desc匹配`返工\|重装\|拆` → 暂NVA | "装配默认VA：直接形成产品组合" |
| 使用（含加工） | VA | 高 | desc匹配`空跑\|试运行\|对刀` → 暂NNVA | "使用/加工默认VA：直接改变形态或性能" |
| 取放 | NNVA | 高 | 无（取放压缩靠建议引擎处理） | "取放默认NNVA：取放辅助动作，可缩短距离、降动作等级" |
| 预对 | NNVA | 高 | dur_s>2 → 暂NVA | "预对默认NNVA：定位辅助；超2s提示可治具定向消除"（裁决2026-10-21：总体蓝图4.1/7.2矛盾，定稿按NNVA，01词表已同步冻结进RV1.0） |
| 检验 | NNVA | 高 | desc匹配`返检\|重复\|自设\|抽检复查` → 暂NVA | "检验默认NNVA（有规范依据）；疑似无依据/重复，请确认品质文件依据" |
| 搬运 | NNVA | 高 | desc匹配`往返\|再次\|回.取` → 暂NVA | "搬运默认NNVA：工序物流必需；疑似同工位往返搬运，请确认" |
| 等待 | NVA | 高 | desc匹配`节拍\|同步\|配合\|机` → 暂NNVA | "等待默认NVA；疑似节拍设计缓冲/人机配合等待，请确认" |
| 寻找选择 | NVA | 高 | 无 | "寻找选择默认NVA：目视化缺失/供料未唯一化，目标删除" |
| 持住 | NVA | 高 | 无 | "持住默认NVA：手当夹具用，治具可代" |
| 其他 | 暂NNVA | 低 | 全部进待复核 | "类型为'其他'，规则无法判定，请人工归类" |

规则求值：例外规则排在默认规则之前，按数组顺序首个命中生效（见9.2）。

### 2.2 人工改判流程（改必填理由，零新增表）

| 步骤 | 动作 | 落库 |
|---|---|---|
| 1 | 在待复核队列或要素清单中点要素→选新va_class（VA/NNVA/NVA） | — |
| 2 | 必填改判理由（≥5字，前端校验） | — |
| 3 | 确认 | va_class写入新值；desc**末尾追加**标记：`[VA改判\|原:NNVA\|新:VA\|理由:治具已定向\|人:张三\|2026-10-21]` |
| 4 | 饼图/山积图/平衡率本地即时重算 | t_station.CT等聚合值刷新 |

- **为什么记desc**：t_element无理由/操作人字段，MVP禁止新增表与字段，故用desc尾部结构化标记承载（前端以正则`^\[VA(改判\|确认)\|`解析，解析出的标记不显示在描述正文里）。
- **重算覆盖保护**：自动归类仅当va_class为空、等于规则默认值，或desc不含`[VA改判`/`[VA确认`标记时写入；含标记的要素跳过，防止一键重算冲掉人工裁决。
- **确认动作**：对待复核要素点"确认"=接受暂定归类，desc追加`[VA确认\|类:NVA\|规则:VR08\|人:张三\|2026-10-21]`，同样受覆盖保护。

## 3. 六类浪费触发器（量化条件）

通用约定：仅扫描**当前工位、当前bol_version、outlier_flag=0**的要素；pct = 涉及dur_s ÷ 工位工时 × 100（保留1位小数）。

| 浪费类 | 级别 | 触发条件（可计算） | 数据来源 | 证据文本模板 → 示例 |
|---|---|---|---|---|
| 持住 | 要素级 | type=持住 且 dur_s>2 | type, dur_s | `持住{dur_s}s（要素{element_id}），占用CT的{pct}%` → "持住3.2s（要素E12），占用CT的8.5%" |
| 持住 | 工位级 | Σ(type=持住)÷工位工时≥5% | type, dur_s | `持住合计{sum}s、占CT的{pct}%，超过5%阈值` |
| 重复取放 | 工位级 | COUNT(type=取放)≥6 | type | `单循环取放{count}次、合计{sum}s（{pct}%），建议核查可否合并取放/一次取多件` |
| 重复取放 | 要素级 | COUNT_SAME_DESC(type=取放)≥2 | type, desc | `同一对象"{desc}"取放{count}次、合计{sum}s，疑似重复取放` |
| 搬运 | 要素级 | type=搬运 且 dur_s≥2 | type, dur_s | `搬运{dur_s}s（要素{element_id}），占用CT的{pct}%` |
| 搬运 | 工位级 | Σ(type=搬运)÷工位工时≥5%，或desc匹配`往返\|再次`的搬运≥2条 | type, desc, dur_s | `搬运合计{sum}s（{pct}%），其中疑似往返搬运{n}条` |
| 等待 | 要素级 | type=等待 且 dur_s≥1 | type, dur_s | `等待{dur_s}s（要素{element_id}），占用CT的{pct}%` |
| 等待 | 工位级 | Σ(type=等待)÷工位工时≥10%；或双手空闲段（见第7节）>1s | type, dur_s, hand, start_ms | `等待合计{sum}s（{pct}%）；其中双手同时空闲{idle}s` |
| 寻找选择 | 要素级 | type=寻找选择 且 dur_s≥2 | type, dur_s | `寻找/选择{dur_s}s（要素{element_id}），占用CT的{pct}%` |
| 寻找选择 | 工位级 | Σ(type=寻找选择)÷工位工时≥8% | type, dur_s | `寻找选择合计{sum}s（{pct}%），超过8%阈值，提示目视化/供料唯一化` |
| 检验冗余 | 工位级 | Σ(type=检验)÷工位工时≥15% | type, dur_s | `检验合计{sum}s、占CT的{pct}%，超过15%阈值，建议核查检验合并/自动化检测` |
| 检验冗余 | 要素级 | COUNT_SAME_DESC(type=检验)≥2 | type, desc | `检验项目"{desc}"出现{count}次，疑似无依据重复检验` |

输出给建议引擎的条目结构：`{waste_type, station_id, level, element_ids[], evidence, involved_dur_s}`；est_save_s由建议模块按ECRS映射另行估算（NVA类上界=involved_dur_s全额，NNVA类建议减半——仅作建议模块上界参考，不写库）。

## 4. 计算口径总表（v2.1补丁#3落地）

| 指标 | 口径（逐字段） |
|---|---|
| 要素std_time | `std_time = dur_s × rating × (1 + allowance)`，系统计算列，禁手填（与毕准时模块对齐，见待确认#2）；rating空默认1.00、allowance空默认0 |
| 生效要素 | bol_version=工位当前版本 且 outlier_flag=0 |
| 工位工时（=山积图柱高） | Σ生效要素std_time |
| t_station.CT | 引擎回写=工位工时（同上）；同时写updated_by=触发人、updated_at。**注意：此CT为标准口径，与视频实测循环时间不同**——实测值含异常与波动，MVP统一用ST合计（补丁#3），不另存实测CT |
| t_station.TT | 外部输入：IE主管按"可用时间÷需求产量"配置，引擎只读不回写 |
| 异常要素 | outlier_flag=1的要素：**不进**工位工时、**不进**山积图、**不进**VA占比分母；在分析结果页单独列出"异常要素N条"及各自outlier_reason |
| VA占比 | 分子=Σ(va_class=VA)生效要素std_time；分母=工位工时（同上口径）。NNVA/NVA占比同理 |
| 待复核要素 | 按暂定归类计入分子与分母（饼图可见，不悬空） |
| 工位数N（平衡率用） | 该line_id下有≥1条生效要素的工位数 |

## 6. 平衡率与瓶颈榜

### 6.1 平衡率

```
平衡率 = Σ各工位工时 ÷（瓶颈工位CT × 工位数N）× 100%
```

- 分子=全线各工位工时之和（各站均为"Σ生效且非异常要素ST"口径，见第4节）；
- 瓶颈工位CT=全线最大工位工时；N=有效工位数（全要素异常的工位不计入，见第11节）。
- **CT与ST口径差异说明**：本口径下各工位的"CT"即"ST合计"（补丁#3），故平衡率衡量的是**工位间负荷均衡度**，不反映增值效率（后者由VA占比单独表达，两者并列展示、不可互相替代）。
- 灯色：<70%红 / 70~85%黄 / ≥85%绿；工位NVA占比>10%另发红旗"该工位NVA占比{pct}%（目标<5%）"。

### 6.2 瓶颈榜（Top 5）

| 项 | 规则 |
|---|---|
| 排序依据 | 主序：可削减空间(CT−TT)降序，CT>TT的工位置顶；同值按CT降序；TT未配置时退化为CT降序 |
| 分级标签 | 硬瓶颈=CT>TT或全线CT最高；次瓶颈=CT≥瓶颈CT×90%；关注站=CT≥瓶颈CT×80% |
| Top N | 5（5~10工位试点线取前5足够） |
| 每行字段 | 工位名 / CT(s) / CT÷TT比（TT缺失显示"—"）/ VA占比% / 主要浪费（该工位涉及dur_s最大的浪费类+合计秒数） |
| 点击行为 | 跳转该工位双手作业图+要素清单（操作分析入口，对应原蓝图"选站逻辑"的MVP简化） |

## 7. 双手作业图自动生成算法

输入：当前工位、当前bol_version、全部要素（含异常，图上区分）的hand/start_ms/dur_s。

```
步骤1  周期边界：T0=MIN(start_ms)，T1=MAX(start_ms + dur_s×1000)，周期T=(T1−T0)/1000（秒）。
步骤2  分轨：hand=L→左轨；hand=R→右轨；hand空→第三条灰色"未分手"轨；outlier要素加斜纹。
步骤3  绘制：每要素一矩形，横轴起点=(start_ms−T0)/1000秒，宽=dur_s，颜色按va_class三色。
步骤4  单手空闲：对每只手求动作区间并集，周期内未覆盖段即该手空闲（黄色段）。
步骤5  双手空闲：左右手同时无动作的时段→红色段；累计>1s输出等待类浪费证据
       "双手同时空闲{idle}s，占周期的{pct}%（要素间隙）"。
步骤6  负荷差：|Σ左手dur_s−Σ右手dur_s| ÷ MAX(两者) ×100%；>20%黄旗"双手负荷差{pct}%，提示物料左右分摆/对称布局"。
```

- 周期边界处理：首要素起点前/尾要素终点后的时间**不画不计算**（视为循环衔接段）；若周期T与t_station.CT偏差>20%，图顶提示"时间轴周期{T}s与CT偏差大，请核查循环边界标记"。
- 双手图仅统计生效要素；异常要素画出但加斜纹并注记outlier_reason。

## 8. 饼图数据结构与"待复核"队列

### 8.1 饼图（默认当前工位，可切换全线汇总）

```json
{ "va_s": 12.4, "nnva_s": 8.1, "nva_s": 3.2,
  "va_pct": 52.3, "nnva_pct": 34.2, "nva_pct": 13.5,
  "outlier_count": 1 }
```

### 8.2 待复核队列（运行时派生视图，非表，不入库）

队列=当前工位当前版本下，**desc无`[VA改判`/`[VA确认`标记**且命中低置信度规则的要素集合，实时重算生成：

| 字段 | 来源 |
|---|---|
| element_id / seq / type / desc / dur_s | t_element |
| 暂定归类 | 规则表result_class |
| 判定理由 | 规则表reason_template填充 |
| 触发规则编号 | 规则表rule_id |

处理动作：①**改判**（2.2流程，写desc标记）；②**确认**（接受暂定归类，写确认标记）。
清空条件：队列内全部要素均已改判或确认即显示"已清空"；因标记受重算覆盖保护，清空后再次重算**不会**重新入队。队列不为空时饼图旁显示"待复核{n}条"角标提醒。

```json
  "waste_rules": [
    { "rule_id": "WT01a", "waste_type": "持住", "scope": "element",
      "condition": "type == '持住' AND dur_s > 2",
      "evidence_template": "持住{dur_s}s（要素{element_id}），占用CT的{pct}%" },
    { "rule_id": "WT01b", "waste_type": "持住", "scope": "station",
      "condition": "SUM(type == '持住') / STATION_CT >= 0.05",
      "evidence_template": "持住合计{sum}s、占CT的{pct}%，超过5%阈值" }
  ]
}
```

字段约定：va_rules四要素+置信度；waste_rules=编号/浪费类/作用域(element|station)/条件/证据模板。模板变量：{dur_s} {element_id} {desc} {pct} {sum} {count} {idle}——全部由规则引擎填充，禁止LLM生成。

### 9.2 条件表达式语法（杜绝歧义）

```
表达式   := 项 ( ('AND'|'OR') 项 )*        可用圆括号分组，AND优先于OR
项       := 字段 比较 值  |  字段 '~' '正则'
字段     := type | desc | dur_s | seq | hand | va_class | outlier_flag | start_ms
比较     := == | != | > | >= | < | <=       数值比较按数字，字符串按精确等值
值       := 数字（秒）| '单引号字符串'
"default" := 无条件命中（该要素类型的默认规则）
内置函数（仅station作用域）: SUM(元素条件)=满足条件要素dur_s合计；
  COUNT(元素条件)=计数；COUNT_SAME_DESC(元素条件)=同desc最大重复计数；
  常量 STATION_CT=工位工时
```

求值规则：va_rules按数组顺序**首个命中生效**（例外规则必须排在默认规则之前，规则文件生成时按"例外→默认"排序，由维护人保证，W8冻结时校验）；waste_rules**全部命中即输出**（不短路）。

### 9.3 版本号规则

- 格式`RV主.次`：阈值/正则调整升次版本（RV1.0→RV1.1）；增删规则或改结果类升主版本（RV1.1→RV2.0）。
- 每次分析输出在报告页脚标注"规则版本RV1.1·数据版本v(3)"，无字段可存则不落库、仅随报告展示。
- 规则更新后须手动触发一键重算（第10节），旧分析不追溯。
