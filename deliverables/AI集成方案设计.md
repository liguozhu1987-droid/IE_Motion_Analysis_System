# IE 改善平台 · 系统 AI 集成方案设计（v3.53 候选）

> 状态：**设计方案 · 待评审**。本文只做架构与机会设计，未改动任何代码/配置。
> 设计日期：2026-10-28 ｜ 基于现状：v3.52（单文件 SEA 发布形态）
> 产品哲学红线：工具做「薄」——帮 IE 更快看出问题 → 留；帮管理层管住 IE → 砍。
> AI 三铁律：①AI 永远「待审」；②LLM 禁产数字（定量一律规则算）；③模拟值绝不回写正式 ST。

---

## 1. 目标与边界

**目标**：在不推翻现有「人拆 AI 校」主线与三层 AI 架构的前提下，识别**尚未 AI 化或 AI 可增强**的模块，给出低成本、可开关、可回退的集成机会，使 IE 工程师与管理者「更快看出问题、更快生成改善文案」。

**硬性边界（必须遵守，来自项目记忆）**：
- 所有新增 AI 复用现有 `ai.module` 的 LLM 封装 + mock 兜底 + `ai_enabled` 开关，**不新建一套 LLM 调用链**。
- LLM 只产**自然语言文案/解读/建议**，**绝不产数字**；任何定量结论（平衡率、节省秒数、瓶颈判定）继续由规则引擎服务端算。
- AI 产出默认「待审」，人工确认后才进入正式数据。
- 成本敏感：默认 `ai_enabled=false`；非必要不上云 LLM，优先本地规则/本地 embed/ffmpeg 等零边际成本手段。

## 3. AI 集成机会矩阵（按模块）

> 优先级：**P0 = 高价值·低成本·契合「帮 IE 看出问题」→ 建议优先**；P1 = 中价值需评估；P2 = 探索/谨慎（涉管理层「管住 IE」红线或高风险）。

| # | 模块 | 当前状态 | AI 集成机会 | 类型 | 价值 | 成本 | 优先级 |
|---|---|---|---|---|---|---|---|
| 1 | **analysis 分析** | 规则算平衡率/瓶颈 | LLM 基于要素分布（VA/RNVA/NVA 占比、双手失衡、持住/延迟）生成**根因诊断 + 改善方向**自然语言报告 | 文案解读 | 高 | 中 | **P0** |
| 2 | **compare / diff** | diff 纯函数算差异(15/15) | LLM 对前后版本/多工位差异生成**变化解读 + 倒退预警**（如 NVA 占比上升） | 文案解读 | 中高 | 低 | **P0** |
| 3 | **videos / ai-segment** | 人工标记起止 | ffmpeg/CV **自动镜头切分预分段**，减少人工起止标记 | 预处理 | 中 | 低(本地) | **P0** |
| 4 | **ai-waste 知识库** | 关键词规则检索 | 升级为**向量语义检索**召回历史改善案例，提升建议/浪费命中质量 | 检索增强 | 中 | 低-中(本地embed) | P1 |
| 5 | **SOP（v3.44 对齐）** | 词表对齐人工编 | LLM 基于已确认要素序列生成**标准作业组合(SOP)草稿**文案 | 文案生成 | 中 | 低 | P1 |
| 6 | **dashboard / audit** | 聚合展示 / 审计候选 | LLM 对审计日志/权限变更/复测操作生成**异常摘要**（频繁复测、批量改判） | 文案摘要 | 中(管理层) | 低 | **P2（谨慎，涉「管住IE→砍」红线）** |
| 7 | **stations / lines** | 人工建 | 从 CMC 主数据/文件名**自动建议命名/分类/工时区间** | 轻量辅助 | 低 | 低 | P2 |
| 8 | **自然语言查询（驾驶舱）** | 无 | 管理层 NL 问「哪条线 NVA 最高」→ 转结构化查询 | 对话式 | 高(探索) | 高 | **探索（高风险：越权/注入/成本）** |

## 4. 分层架构设计（复用，不另起炉灶）

### 4.1 新建「AI 洞察服务层」`ai-insight`（建议）
将散落在各页的「诊断/解读/摘要」三类**纯文案生成**统一收敛到一个模块：
- 复用 `ai.module` 的 LLM 客户端封装（profile 启用位、mock 兜底、`ai_enabled`）。
- 暴露 3 个纯函数式服务：`diagnose(要素分布)→文案`、`interpret(diff结果)→文案`、`summarize(审计/操作流)→文案`。
- 所有输出带 `source='ai'`、状态 `pending_review`，**不触碰任何数字字段**。
- 调用方：analysis 页、compare/diff 页、audit 页（P2）。

### 4.2 视频预处理增强（不进 LLM）
- 在 `videos` 模块复用已打包的 `ffmpeg`，加一个**镜头/场景切分**步骤，输出候选片段起止点供人工确认（不自动落要素）。零 LLM 成本。

### 4.3 知识库向量化（P1，可选）
- 在 `ai-waste` 现有 `t_ai_waste_kb` 上加 `embedding` 列，用**本地 embedding 模型**（或轻量云端）做语义召回，替代纯关键词 `keywords` 匹配。
- 召回结果注入 prompt「历史经验参考」段（沿用 v3.51 反哺闭环），`hit_count++` 逻辑不变。

### 4.4 AI Agent 任务队列（架构增强，候选池已列）
- 把分解 / 建议 / 浪费 / 诊断 等 AI 任务编排为**可监控的任务队列**（状态、重试、超时、mock 降级），提升可靠性与可观测性，不改业务口径。

## 5. 优先级与实施路线（建议）

**阶段一（P0，低成本高价值）— 【已确认首批，并提前纳入 P1 知识库】**
1. 分析诊断智能体（analysis + ai-insight）
2. 对比差异解读（compare/diff + ai-insight）
3. 视频自动切分预处理（videos + ffmpeg）
4. 知识库向量化（ai-waste，由阶段二提前至首批，用户 2026-10-28 确认）

**阶段二（P1，需评估成本）**
4. 知识库向量检索（ai-waste）
5. SOP 草稿生成（SOP 词表 + ai-insight）

**阶段三（P2 / 探索，需你拍板）**
6. 审计异常摘要（涉「管住 IE」红线，可能砍）
7. 工位/线智能命名（低价值）
8. 自然语言查询（高风险，需严格护栏，探索）

**上线门禁（沿用你的产品哲学）**：每个 AI 功能须过「周活≥3 + 采纳≥50%」闸门才留；`ai_enabled` 开关 + mock 兜底；非必要不上云 LLM。

## 6. 风险与成本控制

| 风险 | 缓解 |
|---|---|
| 成本（你最敏感） | 默认 `ai_enabled=false`；P0 多为本地/规则手段；LLM 文案仅在确认启用后计费；mock 兜底保证关停不影响主流程 |
| LLM 幻觉产数字 | 铁律②：LLM 输出层剥离数字，定量一律规则算；产出待审 |
| 数据主权（内网） | 优先本地模型/规则；视频/工艺数据不外发；向量库本地存 |
| 越权/注入（NL 查询） | 阶段三才考虑，Text-to-SQL 严格白名单 + 租户隔离 + 只读，不写 CMC |
| 准确率不足 | 全部「待审」，人工确认前不进正式数据；低采纳即砍 |
