1. 现状诊断为什么用户不知道从何下手

当前系统登录后的首页即"工位清单"页（#/stations），一页平铺：选线下拉 + 4 个指标卡 + 工位卡片网格 + 改善建议表。功能能跑，但结构对新手不友好、入口对角色不区分、上下文对操作不连续。逐条诊断如下：

#问题具体表现（代码事实）后果严重度
1首页没有回答"我现在该做什么" 首页只呈现"有哪些工位"，没有待办、没有任务引导、没有"继续上次" IE 人员流动大（项目已知痛点），新人首次登录面对空列表/陌生列表直接迷失高
2模块入口埋没 改善建议表嵌在工位清单页底部；收益参数埋在对比页内；用户管理只是顶栏一个文字链接；规则库有 API 无前端页 "生成建议→采纳→流转→复测→对比"闭环被拆散在不同页面深处，用户找不到高
3工位上下文不连续 工作台/分析/对比三个页面靠 hash 路由的 ctxId 串联，当前工位只在顶栏导航隐现，无面包屑、无页签 刷新、分享链接、多点对比后"我在测哪个工位"不直观；三页之间切换要回顶栏找中
4角色无差异化首页 sys_admin / ie_engineer / line_leader / viewer 看到完全相同的首页 管理员找不到待审批入口（要手动输 #/admin/users）；班长只关心本线却被全量数据淹没中
5空状态无引导 无工位时仅一行"该产线暂无工位"；无建议时提示"先到分析页生成建议" 冷启动用户不知道第一步是建工位、导 CSV 还是看演示中
6布局无扩展性 顶栏横排导航，模块增至 6+ 个必然拥挤；无侧边栏/无分组 后续加规则库、审计页、报表页时只能继续堆顶栏中
诊断结论：问题不在功能缺失，而在信息架构——页面按"技术模块"组织而不是按"IE 改善工作流"组织，首页按"数据展示"设计而不是按"任务待办"设计。本方案只重排入口与层级，不新增任何管理模块、不动业务计算口径（符合产品哲学"工具做薄不做全"）。

2. 设计原则行业最佳实践 → 本平台落地

编号原则行业依据本平台落地
P1工作流驱动，而非功能驱动 OTRS10 按 KAIZEN 循环组织：拍视频→分析→消除浪费/标准化→输出手册→培训传承，用户始终知道自己在循环哪一步 按 IE 改善闭环六步组织导航：定对象 → 测现状 → 找浪费 → 出方案 → 验效果 → 固标准，每步对应现有页面
P2三层信息架构 B 端经典分层：全局总览 → 项目/产线维度 → 单对象工作区 全局仪表盘（首页）→ 产线驾驶舱（#/stations）→ 工位工作区（工作台/分析/对比）
P3待办驱动首页 门户型 B 端系统（OA/MES 看板）首页=待办+指标+快捷入口，而非数据罗列 首页回答"现在做什么"：待审批、待实施建议、待复测验证、最近访问
P4左树右表 + 面包屑保上下文 左树右表是中后台最经典模式；工业软件导航规范：树形承载层级（产线→工位），选中态明确 产线树/工位切换常驻或面包屑显性化，任何页面可见"我在哪个工位"
P5权限自适应入口 RBAC 系统的导航应按权限过滤，无权限入口不渲染（后端仍有 403 双保险） 复用现有 can()：导航、首页卡片、操作按钮全部按 permission 过滤
P6零新增管理模块、近零后端改动 MVP 纪律：只保留能直接促进 IE 分析与改善效率的能力 只重排入口/新增 1 个仪表盘页 + 2 个已有能力的独立入口页；后端一期 0 个新接口

选型建议：A（主体）+ B 的元素（吸收）

  • 主体选 A：只有"待办驱动的门户首页"能直接回答用户提出的"进入后该从何下手"；侧边栏同时解决扩展性问题。
  • 吸收 B 的两个元素：① 工位工作区采用面包屑 + 三页签（分解/分析/对比）替代顶栏跳转，实现"上下文常驻"的大部分收益，但不引入常驻左树（保时间线/山积图宽度）；② 产线驾驶舱保留工位切换下拉（ctxId 显性化）。
  • 演进路径：先按 C 的精神快速上"首页仪表盘 + 三步引导"（第 1 迭代，0.5 天即可体验），再切 A 的侧边栏骨架（第 2 迭代）——即 A 的落地顺序本身就是渐进式的，风险可控。
