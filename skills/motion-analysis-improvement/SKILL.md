# 动作分解增值分析与改善措施清单

## Overview

将「视频动作分解表」转化为可落地的 IE 改善方案。分析流程有严格的先后顺序（这是本技能的核心纪律，不得颠倒）：

```
① 动素增值非增值分析（每个动作要素判定两套正交体系：动素类别按动素名称客观判定〔18动素学〕＋ 增值性主分类 VA/RNVA/NVA〔精益〕；增值比例只按主分类计算）
        ↓
② 5W2H 提问（按要素性质决定提问重点，覆盖全部动作要素 → 识别问题）
        ↓
③ ECRS + 动作经济原则 拟定改善方案（注意：是拟定方案，不是最终确定方案）
        ↓
④ 评审确认（用户在「是否适用」下拉选择；适用者填写「预期缩短或消除(秒)」）
        ↓
⑤ 汇总指标自动联动更新（最终结果只联动「适用」×「预期缩短或消除(秒)」；分析测算值降级为「分析测算参考」区块，不作最终结果）
```

输出 5 个工作表：汇总指标 / 动素增值分析 / 5W2H提问 / 改善措施清单 / 口径与说明。
**「防错设计」「落地与ECN」不再单设工作表**——防错技术保留为改善措施清单中的「运用方法」；「改善原则」不在清单列中显示，统一在「口径与说明」页声明。

## Workflow Decision Tree

- 用户提供动作分解表并要求「增值分析 + 改善清单」→ 走完整流程（Step 1-6）。
- 用户只要求 5W2H 提问或只要求增值比例 → 执行对应步骤，仍按本技能口径，但可跳过 Excel 生成。
- 输入表无 CT 列 → 先确认能否换算（时间序列值 ×86400），无法换算时向用户澄清，不要臆测。
- 数据存在问号标记（如「清理脏污？」）→ 按 Step 3 的疑点处理规则，不要直接计入基线。

## Step 1: 读取并规范化动作分解数据

委派表格子代理（sheet-agent）读取源 Excel，要求返回：所有工作表名称与用途、完整逐行数据（不省略）、时间列的原始值与秒换算、疑点标记。核对要点：

- 确认时间列是否为 Excel 时间序列值（按天小数存储），**秒 = 原值 × 86400**。
- 保留 Distance 列的肢体部位（大臂/小臂/手腕/低头仰头/迈步/弯腰）与设备并行状态备注——这是动作经济与人机联合作业分析的关键输入。
- 记录总 CT（合计行）与动作步数作为基线。

## Step 2: 动素分类判定（两套正交体系，核心，先于 5W2H）

按 `references/methodology.md` 第 2 节口径，对每个动作要素判定**两套正交的体系**，严禁混用：

**主分类维度（增值性，汇总统计用）**——按精益价值判定，写入明细 F 列「类别归属」，只用三个枚举：
- `增值(VA)`：直接改变产品装配连接/标识/防护状态 → **尽量缩短**
- `必要非增值(RNVA)`：检验、追溯扫码、触发报工等必要但不创造客户价值 → **尽量取消，无法取消则尽量缩短**
- `非增值(NVA)`：取放、步行、弯腰、等待等纯消耗 → **尽量消除**

**动素类别（18动素学口径，另列）**——按动素名称客观判定，由生成器公式从「动素名称」列自动推导（明细 E 列），组装数据时不填：
- 有效动素：伸手(TE)、握取(G)、移物(TL)、放置、定位(P)、松手(RL)、检查(I)、装配(A)、使用(U)、拆卸(DA)
- 辅助动素：寻找(SH)、发现(F)、选择(ST)、思考(PN)、预置(PP)
- 无效动素：持住(H)、可避免延迟(AD)、不可避免延迟(UD)、等待

**正交铁律**：两套体系互不推导——有效动素不一定增值：检查(I)属有效动素但为必要非增值(RNVA)；伸手/握取/移物/放手属有效动素但多为非增值(NVA)；无效动素必为非增值，但非增值不一定是无效动素。**增值比例、汇总统计一律以「类别归属」为准；动素类别只用于动作方法分析，另列统计、不参与增值比例计算。**

历史反面案例（本技能必须避免）：曾把精益增值三分法的枚举值直接命名为「有效动素/辅助动素/无效动素」，与动素学分组名称冲突，导致「伸手/握取/移物/放手/检查」这些第一类有效动素被错标为「无效/辅助动素」。

其余纪律不变：检查(I)须在「动素名称」保留原名形成双重标注，否则增值比例虚高会掩盖人机闲余改善靶心；收益不重复计列，无量化收益写数字 0；**重复操作先判时序可行性再谈节省**（步骤 2.1）；**设备/天窗自动运行及运行窗口内检测提速≤10%封顶**（步骤 2.2）。

计算并交叉校验：增值比例 = 增值(VA)秒数 ÷ 总 CT，RNVA/NVA 占比同理；**动素明细「测算可优化秒」合计必须等于措施清单「测算参考秒」合计**（生成器内置校验，不等则报错拒绝生成）。

### 步骤 2.1：重复操作的时序可行性分级与折算（必做）

对「多次同样的操作」（反复扫码、反复取放同一工具、多次按确认键），逐条按 `references/methodology.md` 第 2.4 节的四级矩阵 A/B/C/D 判定后才提出合并建议：

- **A 时序锁定**（如扫框架码启动设备）：动作不可取消，可改固定式/免持扫码方式，节省计 **0**。
- **B 系统可合并**（同系统重复采集）：提出「一次扫码双记录」但标注「需 IT 确认、保留必要时序」，节省**按实现概率系数 0.5~0.8 折算**，不写全额。
- **C 工具可替代**（取放/瞄准类）：固定式扫码器按扫码点覆盖率系数 0.7~1.0 折算，覆盖不到点保留手持。
- **D 纯浪费**：ECRS 全额消除。

折算系数必须写明依据；验证指标必须含「扫码时序合规率 = 100%」，防止现场为追 CT 跳过必要扫码或检点。

### 步骤 2.2：设备/天窗自动运行与检测的提速上限（≤10%，必做）

对**设备自动运行、天窗/遮阳帘自动运行，以及运行窗口内的检测/检查作业**，无专项提速措施（设备提速改造、检测自动化等且经 3-5 循环实测）时，压缩上限 = 原时长 × 10%，且须写明检点定量 SOP 等支撑措施。把检测时间压到某个「经验值」而无可靠依据 → **不予采信，回退到 10% 封顶**。

反面案例：遮阳帘运行检查 24.82s 以「定量化至 12-15s」为由缩减 10s（约 40%）无措施支撑 → 正确做法为 10% 封顶计 2.48s。配套约束：「检点优先、备料在后」人机并行仍可做，但收益**不通过压缩检点时长实现**，备料收益在备料步骤就近化中单列，避免重复计量。

## Step 3: 5W2H 提问（在增值分析之后、措施拟定之前）

**顺序纪律：先判定要素性质，再按性质提问**——VA 动素重点问 How（如何缩短动作等级与距离）；RNVA 动素重点问 Why/Can（为何必要、能否取消合并或系统替代）；NVA 动素重点问 Why 存在与 How 消除。

- 疑点分组**必须覆盖全部动作要素**（可按工艺段落分组，如取放扫码枪 4/5/6 一组），每组标注「要素性质」（VA/RNVA/NVA/组合）。
- 每组给出：5W2H 提问（What/Why/Who/Where/When/How/How much）→ 核心问题（识别的问题）→ 分析结论（倾向性答案）→ 对应拟定措施编号。
- 必问的典型疑点：①起身/坐下等待；②重复扫码/重复取放同一工具；③手工撕背纸等精细动作；④清理脏污（带问号）；⑤长时检查中的人机闲余；⑥重复按完成按钮；⑦弯腰/低头姿态；⑧双手作业有无单手闲置。
- 详细提问范式见 `references/methodology.md` 第 1 节。

## Step 4: 改善机会识别与拟定方案（ECRS）

根据 5W2H 识别的问题，用以下手法**拟定**改善方案（措辞用「拟定，待现场验证/需 IT 确认」，不得写成已定案）：

- **人机联合作业**：找设备自动运行窗口，设计「检点优先、备料在后」并行；注明节省的是备料排队时间而非检查时间，备料不得干扰检点专注。
- **ECRS**：逐条给出取消/合并/重排/简化机会（E撕背纸→预剥离打印机；C双枪合一、检查+备料并行；R报工前移、打印时机前移；S固定式扫码器、撑袋治具、高位磁吸座）。
- **动作经济四方面**：动作数量、动作距离、轻松作业、双手作业，分别列清单。
- **三维度**：现场物品布置（就近化/悬挂/滑道/磁吸）、身体运用（动作等级降级、弯腰低头起坐消除）、工具设备运用（固定扫码器、预剥离打印机、撑袋治具）。
- **防错技术**：作为运用方法纳入措施清单（互锁/断根/保险型装置），并保留硬约束「防错互锁须与效率改善同步或先行发布」。
- **线体再平衡/布局优化**：改善后 CT 纳入山积图复核瓶颈归属，评估拆分重排。

## Step 5: 组装数据并生成 Excel

按 `assets/data_template.json` 的字段契约组装 JSON 数据文件，注意：

- `motion_rows`（8字段）/ `w2h_rows`（7字段）/ `measures`（12字段）/ `def_rows`（6字段）的**字段顺序即 Excel 列顺序**，不可调换；以 `_comment` / `_enum` / `_rule` 开头的说明行组装时删除。
- **不要提供「是否适用」「预期缩短或消除(秒)」的值**——这两列是生成器自动追加的用户输入区。
- measures 第 12 位「测算参考秒」须与明细「测算可优化秒」归属一致；生成器交叉校验 Σ(测算参考) == Σ(明细测算可优化)。
- 实施批次只用 `当周 / 2-4周 / 1-2月 / 长期` 四个值。

运行生成脚本：

```bash
python scripts/build_checklist.py <data.json>
```

脚本输出 5 个工作表，结构如下：

| 工作表 | 内容 | 关键机制 |
|---|---|---|
| 汇总指标 | 一核心指标·现状 / 二评审确认结果(最终口径,金色强调) / 三主分类统计·增值性 / 四动素学三分类(正交另列) / 五改善措施统计(批次) / 六分析测算参考(未经确认,降级区块) / 七结论 | 最终结果只联动「适用」×N列（SUMIF）；主分类统计联动明细「类别归属」；动素类别统计另列、不参与增值比例；测算值单独降级为参考区块并标注未经确认 |
| 动素增值分析 | 逐要素判定（动素名称＋双重分类） | E列「动素类别」按动素名称公式客观判定（动素学，正交另列）；F列「类别归属」为增值性主分类（增值VA/必要非增值RNVA/非增值NVA），下拉枚举、驱动汇总统计 |
| 5W2H提问 | 按要素性质分组的提问与结论 | 位于措施之前，体现分析顺序 |
| 改善措施清单 | 拟定方案 + 用户输入区 | M列下拉(适用/不适用)、N列留空待填(黄色)、L列测算参考 |
| 口径与说明 | 三分类口径 / VA-RNVA-NVA代码 / 输入区说明 / 折算与封顶纪律 | 改善原则在此页声明 |

汇总表所有核心指标写 Excel 公式并与明细联动（COUNTIF/SUMIF/COUNTIFS/SUM/COUNTA/IF+OR 保护），脚本内置缓存值注入：把 Python 侧算好的值写回公式单元格的 `<v>`（字符串结果自动设 `t="str"`），预览器与 `data_only=True` 打开即显示数值。执行后核对终端打印的 `CACHE_INJECTED`（应等于公式总数）与 STATS，确认交叉校验未报错。

> 严禁降级为「全部写静态值」方案——用户明确要求改一处明细、其余各处自动更新。本机 `recalc.py` 不可用不是借口，公式 + 自注入缓存已同时满足联动与可见。

若目标输出文件被预览器/Excel 独占锁定导致 `PermissionError`，脚本自动改用同目录 `XXX_公式联动版.xlsx` 文件名交付；手动重生成时同样遵守此规则，不要静默改写静态值版。

## Step 6: 合规标识与交付

1. **双重读取校验（必做）**：`load_workbook(data_only=False)` 应能看到 `=COUNTIF/SUMIF/SUM...` 公式；`load_workbook(data_only=True)` 应能看到数值而非空白；公式单元格中缓存为空的数量必须为 0。另抽查：增值性代码列、SUMIF「适用」联动单元格、合计行。
2. 对成品 xlsx 执行 AIGC 合规标识（须在最后一步，重算或重序列化会覆盖标识）：

```bash
python <workbuddy-sheet-generation>/scripts/aigc_label.py "<output.xlsx>" --platform WORKBUDDY
```

3. 用 present_files 交付文件，并在回复中给出：增值比例与增值性三分类占比（主分类）、动素学类别分布（另列）、**已确认节省合计与按已确认项改善后CT（唯一最终口径）**、测算参考值（注明未经确认）、拟定措施条数与批次分布、**待用户确认事项（在措施清单 M/N 列勾选并填写）**、关键前提。

## Environment Notes

- 本机可用解释器为 `C:/python/python.exe`（自带 openpyxl 3.1.2）；bash 的 `python3` 无 openpyxl 且 pip 安装会报 `0xC000001D Illegal instruction`。
- Windows 控制台默认 cp1252/cp936 编码，脚本打印中文路径会崩；脚本已内置 `sys.stdout.reconfigure(encoding="utf-8")`，自检脚本同样要加。
- 本机公式重算引擎 `recalc.py` 报 `0xC000001D Illegal instruction` 不可用，因此脚本采用「写 Excel 公式 + 自注入缓存值」方案，兼顾联动与打开可见。任何环境都不要改回静态值方案。
- 迭代重生成直接覆盖同一输出文件；被独占锁定则自动改用 `_公式联动版` 文件名。
